# 工艺树序号对齐修复设计

## 问题

Element UI 树形表格会把层级缩进和展开箭头渲染到第一个 `default` 类型列。当前“序号”列是第一个普通列，因此树层级会占用序号列的水平空间，造成两个问题：

- 不同树深度的序号水平位置不一致。
- 带展开箭头的深层节点剩余宽度不足，例如 `45` 被拆成两行。

## 方案

将“序号”列声明为 Element UI 的 `index` 类型，同时保留现有作用域插槽，继续显示后端返回的 `row.idx`。因为 `index` 列不再属于 `default` 列，Element UI 会把树形前缀自动渲染到下一个普通列，即“工艺 / 工序名称”列。

序号文本增加明确的单行约束：

- `display: inline-block`
- `white-space: nowrap`
- `word-break: keep-all`
- 保留等宽数字特性

## 保持不变

- 列顺序仍为序号、名称、工艺编码、工序号、操作。
- 序号继续使用后端 `idx`，不改用表格当前行号。
- 树结构、展开/收起逻辑、查看操作和后端数据均不修改。
- 层级关系仍通过名称列中的缩进和展开箭头表达。

## 验证

- 添加回归测试，确认序号列为 `index` 类型且仍通过插槽读取 `getNodeIndex(scope.row)`。
- 确认序号样式包含禁止换行和禁止字符拆分的约束。
- 运行工艺查看器现有 Node 测试。
- 运行前端 lint 与生产构建。
- 在展开多层工序时检查：所有序号对齐，`45` 不换行，树箭头位于名称列。
