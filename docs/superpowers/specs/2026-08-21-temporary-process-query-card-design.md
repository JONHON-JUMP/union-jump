# 临时工艺 queryCard 树形展示设计

## 目标

优化 MES 工艺卡 `queryCard` 的后端与前端实现。在保留正式工艺分支现状的前提下，补全临时工艺接口参数，将第三方接口返回的工序明细按 `Seqno` 排序并组织成树，最终由 Vue 2 页面展示真实查询结果。

## 范围

- 修改 MES `ProcessServiceImpl.queryCard` 的临时工艺分支。
- 扩展工艺卡响应明细，使其能表达子工序。
- 为 Vue 2 前端新增工艺卡 API 调用，移除当前页面的 Mock 数据。
- 补充后端和前端自动化测试。
- 不实现正式工艺分支，不改造第三方接口协议，不增加工艺编辑能力。

## 请求参数

前端查询表单包含物料号 `prtno` 和工艺规程号 `accno`，请求现有 `/mes/process/query/card` 接口。

临时工艺分支调用第三方接口时按以下规则构造参数：

| 参数 | 规则 |
| --- | --- |
| `prtno` | 使用请求中的物料号 |
| `accno` | 使用请求中的工艺规程号原值 |
| `plndept` | 取 `accno` 前 4 位 |
| `fxtype` | `accno` 长度大于 4 时为 `1`，否则为 `0` |

现有请求校验继续要求 `accno` 非空。临时工艺额外要求 `prtno` 非空；`accno` 不足 4 位时返回明确的参数错误，避免产生无效的部门编码。

## 后端数据流

1. 根据工艺规程号前缀判断正式或临时工艺。
2. 临时工艺按上述规则构造 `TemporaryProcessReqVO` 并调用现有第三方路由服务。
3. 校验第三方响应的 `retCode`、`responseBody`、`oid` 和 `details`。
4. 从明细中确定文档号，通过 `CaoeTableMapper.queryDocInfo` 查询文档信息。
5. 校验文档存在、状态为“已发行”，且 `CaoeDocInfoDTO.oid` 非空。
6. 将第三方 `details` 转换为树形工序明细，构造一张 `ProcessCardRespVO` 返回。

临时工艺卡字段规则：

- `accno`：请求中的工艺规程号。
- `version`：第三方数据没有可靠来源时为空。
- `isFormal`：`0`。
- `isFix`：与计算出的 `fxtype` 数值一致。
- `details`：排序并组树后的一级工序列表。

## 工序排序与组树

第三方字段映射如下：

| 第三方字段 | 响应字段 | 说明 |
| --- | --- | --- |
| `Seqdesc` | `name` | 工序名称 |
| 无 | `code` | 临时工艺没有工序编码，返回空值 |
| `Seqno` | `no` | 工序号，保留原始文本 |
| 无 | `url` | 使用文档 OID 拼接生成 |

查看地址固定为：

```text
http://MESloginUser:MESloginUseradmin@pdm.caoe.com/Windchill/netmarkets/jsp/ext/caoe/mes/export.jsp?oid={caoeDocInfoDTO.oid}
```

排序采用 `Seqno` 各层级的数值比较，而不是字符串比较。例如 `2 < 10 < 10.1 < 10.2 < 11`。排序必须稳定；相同或无法解析的序号保持接口原始相对顺序，无法解析的记录排在有效序号之后。

无点号的工序作为一级节点。带点号的工序以最后一个点号之前的文本作为直接父工序号，例如 `10.1` 的父节点是 `10`。该规则也自然支持多级序号，例如 `10.1.2` 挂到 `10.1`。如果父节点不存在，该记录保留为一级节点，避免丢失接口数据。

`ProcessCardDetailsRespVO` 增加 `children` 字段。`idx` 作为树转换后的稳定展示序号，按深度优先遍历顺序从 1 递增；节点身份与父子关系以 `no` 为准。

## 前端设计

在 `src/api/mes/process` 下新增工艺卡 API 模块，使用现有请求封装向 `/mes/process/query/card` 发送 POST 请求。

页面改造规则：

- 查询表单提供物料号和工艺规程号，两个字段都传给后端。
- 删除 `MOCK_PROCESS_TREE`、本地模拟链接和本地关键字过滤。
- 查询成功后将响应卡片的 `details` 直接传给 Element UI 树形表格。
- 表格通过工序号路径生成稳定行键；工序编码为空时显示 `—`。
- 工序名称使用 `name`，工序号使用 `no`，查看操作使用 `url`。
- 根级摘要展示当前卡片的 `accno`、版本、工序数量和临时/正式标识；空版本显示 `—`。
- 展开、收起和安全新窗口打开行为继续保留。
- 查询失败时清空旧结果，交由现有请求层展示后端错误，避免把上一次结果误认为本次结果。

若后端返回多张卡片，页面依次将每张卡片作为根节点展示；当前临时工艺分支只返回一张卡片，但前端不硬编码单卡限制。

## 异常与兼容性

- `CaoeDocInfoDTO` 为空时返回“临时工艺文档信息不存在”。
- 文档未发行时继续返回“工艺未发行，无法查看”。
- 文档 OID 为空时返回明确的查看地址缺失错误。
- 空明细、响应结构异常继续视为临时工艺查询失败。
- 单条 `Seqno` 非法不导致整张卡失败；该记录排在有效工序之后并作为一级节点展示。
- 重复 `Seqno` 无法形成唯一树关系：第一条作为可挂接的父节点，后续重复项按稳定顺序作为同级节点保留。
- 正式工艺代码路径不在本次设计范围内，不能因临时工艺改造改变其判断条件或协议。

## 测试策略

后端测试先行，覆盖：

1. 临时接口四个参数的组装规则。
2. `Seqno` 的数值层级排序，避免 `10` 排在 `2` 前。
3. `10.1` 挂到 `10`，以及多级父子关系。
4. 父工序缺失、非法序号和重复序号不丢数据。
5. 字段映射以及基于 `CaoeDocInfoDTO.oid` 的 URL。
6. 文档不存在、未发行和 OID 为空的异常。

前端测试先行，覆盖：

1. 查询请求同时发送 `prtno` 和 `accno`。
2. 后端树形明细直接展示，不再依赖 Mock。
3. 空工序编码和空版本的占位显示。
4. 展开/收起与安全外链行为。
5. 查询失败后清空旧结果。

完成后运行相关 Maven 测试、Node 前端测试、Vue ESLint、生产构建和 `git diff --check`。只有 fresh verification 全部满足后才声明完成；仓库既有且与本次无关的告警会单独说明。
