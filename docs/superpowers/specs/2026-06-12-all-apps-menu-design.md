# 全部应用菜单设计

## 目标

将首页底部“全部应用”从现有的扁平应用抽屉改为分层菜单视图。新视图沿用首页现有的视觉语言，并仅展示当前用户有权限访问的菜单。

“全部应用”主体必须放在新 Vue 文件中，由 `jonhonjump-ui/jonhonjump-ui-admin-vue2/src/views/index.vue` 引用。首页继续负责控制打开、关闭和最终路由跳转。

## 数据来源

- 使用 Vuex getter `permission_routes` 作为菜单数据源，不新增后端接口。
- 忽略 `hidden` 为真的菜单、通配路由、404 路由和首页路由。
- 保留权限路由的一级、二级、三级层级，不使用当前首页的扁平化菜单结果渲染全部应用。
- 相对路径基于父级路径逐层拼接；HTTP/HTTPS 地址保持原样并在新窗口打开。
- 无标题、仅用于路由布局的节点应向上折叠，使其可见子菜单进入正确的展示层级。

## 页面结构

### 容器

- 继续使用从页面底部打开的 Element UI drawer。
- drawer 内渲染新建的“全部应用”组件。
- 组件背景、颜色、圆角、阴影、字体、间距和图标风格与当前首页一致，不引入新的后台管理风格。

### 左侧一级菜单

- 左侧纵向展示用户可见的一级菜单。
- 默认选中第一个包含可打开菜单的一级菜单。
- 点击一级菜单，仅切换右侧内容，不触发路由跳转。
- 当前项使用首页主蓝色强调，其余项使用首页的浅色文字和悬停反馈。

### 右侧二级菜单

- 右侧使用首页应用区域同款图标网格展示当前一级菜单下的二级菜单。
- 二级菜单展示图标、名称，并可选展示简短辅助文字。
- 没有三级菜单的二级菜单点击后直接打开对应路由。
- 有三级菜单的二级菜单显示为文件夹应用，不直接跳转。

## 文件夹表现

- 文件夹外观参考移动端应用文件夹：一个大圆角图标容器内排列其全部三级菜单的小图标。
- 内部预览不限制为 9 个，必须包含全部三级菜单。
- 小图标根据三级菜单数量自动计算尺寸和网格列数，在固定文件夹图标范围内缩放排列。
- 当三级菜单数量较多时，优先保证全部项目均可见；预览小图标不显示文字，完整名称在打开文件夹后展示。
- 文件夹下方显示二级菜单名称。

## 打开文件夹

- 点击二级文件夹后，在 drawer 内容上方打开居中的半透明文件夹面板。
- 面板沿用首页的浅蓝、毛玻璃、圆角和阴影效果。
- 面板标题为二级菜单名称。
- 面板内以应用图标网格展示全部三级菜单，每项显示图标和名称。
- 点击三级菜单后关闭文件夹面板和全部应用 drawer，并执行路由跳转。
- 面板提供明确的关闭按钮；点击遮罩或按 Escape 也可关闭。

## 搜索

- 保留全部应用搜索输入框，并沿用首页搜索框样式。
- 搜索范围包含一级、二级和三级菜单名称。
- 搜索时右侧展示匹配的可打开菜单结果，结果使用首页应用图标样式。
- 搜索结果中的二级叶子菜单和三级菜单可直接打开。
- 若匹配的是含三级菜单的二级文件夹，则点击后打开该文件夹面板。
- 清空搜索后恢复一级菜单与二级菜单的分栏视图。

## 组件接口

新组件接收：

- `visible`：控制 drawer 显示。
- `routes`：当前用户权限路由树。

新组件发出：

- `update:visible`：同步 drawer 打开状态。
- `open`：携带规范化后的菜单项，由首页执行跳转。

菜单树规范化、文件夹预览布局和搜索过滤放在新组件内部，首页不再维护 drawer 的扁平菜单与搜索状态。

## 响应式行为

- 桌面端保持左侧一级菜单、右侧图标网格。
- 窄屏时左侧一级菜单改为顶部横向滚动标签，二级菜单保持图标网格。
- 文件夹弹层在窄屏下接近全宽并限制最大高度，内容区域可滚动。
- 图标网格列数根据可用宽度自动减少。

## 边界情况

- 没有可见菜单时显示空状态，不显示无效一级菜单。
- 一级菜单没有二级节点但自身可打开时，将其作为右侧可打开应用展示。
- 三级菜单超过常见数量时，文件夹预览继续展示全部缩略图，打开后的面板通过滚动容纳。
- 超过三级的权限树节点继续折叠到三级菜单集合中，确保所有最终可打开叶子菜单均可访问。
- 路由跳转失败不在组件内吞掉；沿用首页现有路由行为。

## 验证

- 使用包含二级叶子、三级菜单、隐藏菜单、相对路径和外部链接的菜单树验证规范化结果。
- 验证切换一级菜单、打开和关闭文件夹、点击三级菜单、搜索与清空搜索。
- 验证文件夹预览在三级菜单数量少和数量多时均展示全部小图标。
- 运行项目 ESLint，并通过本地页面在桌面与窄屏尺寸下检查布局。
