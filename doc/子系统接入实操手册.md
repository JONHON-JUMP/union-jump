# 子系统接入实操手册（2026-09 修订版）

> **本文只讲子系统自己要做什么、提供什么**。JUMP 侧（系统登记、菜单登记、接口配置、花名册管理）由门户管理员在管理后台操作，子系统只需要把信息报给管理员（各节末尾有"交给门户管理员"清单）。
>
> 接入 JUMP 有三个面，相互独立：**① 页面挂菜单（免登录）→ 必做；② 人员接口（建用户自动开账号）→ 按需；③ 反向调用 JUMP（机端刷卡等）→ 可选**。
>
> 参照工程：**若依 → 照 4200**（`ruoyi4200-master`）；**芋道 → 照 TFMS**（`TFMS-master/tfms`）；**Camstar/外链 → 照现网 CamstarPortal（:4200）与「Camstar人员管理」接口配置**。

## 〇、对号入座：你的系统需要啥（先看这里）

**所有系统共用的 3 个前提：**

| # | 前提 | 说明 |
|---|---|---|
| 1 | **工号对得上** | JUMP 一律以工号（username）为唯一标识；子系统必须能按工号查到自己的用户，否则页面能开但数据全空 |
| 2 | **认 Cookie `Nancal_Cam_SessionId`** | 值 = `Base64(UTF-8(工号))`。JUMP 登录后自动种下（同 hostname 不同端口自动共享），子系统后端解出工号当"当前用户" |
| 3 | **允许被 iframe** | 响应头不能有 `X-Frame-Options: DENY` / `CSP frame-ancestors 'none'`（自带框架配置 + 前面 nginx/IIS 都要查） |

自测 Cookie 值（Git Bash）：`printf '16358' | base64` → `MTYzNTg=`

3. **交给门户管理员**：四个接口完整地址 + SSO 地址 + 一个调用工号

# 一、页面接入（免登录）

## 1.1 机制速览

**登录即种 Cookie，门户打开链路没有 OAuth 跳转**（旧文档"带 # 走 OAuth"的说法已作废，OAuth 只剩外部系统登记绑定和机端刷卡两个用途）：

```
JUMP 登录（工号）
  → 前端立即写 Cookie：Nancal_Cam_SessionId = Base64UTF8(工号)，path=/
  → 点子系统菜单 → iframe 打开（同 hostname 不同端口 Cookie 自动共享；
    跨机时后台隐藏 iframe 调子系统站点的 camstar-cookie-bridge.html 种 Cookie，不阻塞打开）
  → 子系统后端解 Cookie → 工号 → 当"当前用户"
```

**菜单二分规则**（JUMP 侧登记规范，`utils/portalMenuKind.js` 是权威）：

| 类型 | 菜单怎么配 | 打开方式 | 对子系统的要求 |
|---|---|---|---|
| **直开型（Camstar/外链）** | 路由地址填**完整 http**（如 `http://192.168.240.127:4200/Process/...`），组件路径**留空** | iframe 直开该 URL | 页面完整 URL 直达（**history 路由**；hash 的 `#` 会被判成若依型） |
| **若依型** | 组件路径填 `system/xxx`（或 link 带 `#`） | iframe 打 `{systemUrl}/#/{路由}`；菜单树由 JUMP 门户渲染 | hash 路由没问题；页面靠 Cookie 过接口鉴权 |

## 1.2 通用确认（4 项）

| # | 检查项 | 说明 |
|---|---|---|
| 1 | **直开型必须 history 路由**（URL 不带 `#`） | 4200 `vue4200/src/router/index.js:935`、TFMS `ui/src/router/index.js:458` 均为 `mode: 'history'` |
| 2 | **工号体系打通** | Cookie 解出的工号，子系统能查到用户（本库用户表/工号字段/员工视图） |
| 3 | **部署形态** | 同 hostname 不同端口 = Cookie 自动共享，零额外工作；跨机 = 子系统站点根目录放 `camstar-cookie-bridge.html`（见 1.5.2 第 4 条） |
| 4 | **响应头不拒绝 iframe** | 框架默认放行：4200 `SecurityConfig.java:135`、TFMS `MesWebSecurityConfigurerAdapter.java:117` 都有 `frameOptions().disable()`；前面有 nginx 的确认没配 `X-Frame-Options DENY` / CSP |

## 1.3 若依子系统改造（照 4200）

### 1.3.2 新建 `framework/interceptor/CamstarInfoInterceptor.java`

以 4200 同名类为蓝本，修掉了它的几个坑（白名单配置化、Cookie 命中即 break、401 有响应体）：

```java
package com.ruoyi.framework.interceptor;

import com.alibaba.fastjson2.JSON;
import com.ruoyi.common.annotation.Anonymous;
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.common.core.domain.entity.SysUser;
import com.ruoyi.common.utils.StringUtils;
import com.ruoyi.common.utils.SecurityUtils;
import com.ruoyi.common.utils.servlet.ServletUtils;
import com.ruoyi.framework.security.LoginUser;
import com.ruoyi.system.service.ISysUserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.net.InetAddress;
import java.util.Base64;
import java.util.List;

/**
 * 从 Cookie Nancal_Cam_SessionId(Base64工号) 识别当前登录用户（参照 ruoyi4200）
 */
@Component
public class CamstarInfoInterceptor implements HandlerInterceptor {

    public static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";
    /** 业务错误码：前端据此识别"门户身份失效" */
    public static final int UNAUTHORIZED_CAMSTAR = 4001;

    @Autowired
    private ISysUserService userService;

    /** 白名单 uri（contains 匹配）：本系统无需识别用户的接口 */
    @Value("#{'${camstar.whitelist:}'.split(',')}")
    private List<String> whitelist;

    /** 生产服务器 IP：非此 IP 视为开发环境 */
    @Value("${camstar.server-host-ip:}")
    private String serverHostIp;

    /** 开发环境测试工号 */
    @Value("${camstar.dev-user-code:}")
    private String devUserCode;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 1. @Anonymous（若依自带）标记的接口放行
        if (handler instanceof HandlerMethod) {
            HandlerMethod hm = (HandlerMethod) handler;
            if (hm.hasMethodAnnotation(Anonymous.class)
                    || hm.getBeanType().isAnnotationPresent(Anonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行
        String uri = request.getRequestURI();
        if (whitelist != null && whitelist.stream().anyMatch(u -> !u.isEmpty() && uri.contains(u))) {
            return true;
        }
        // 3. 开发环境兜底：非生产 IP 使用测试工号
        String userCode = resolveUserCode(request);
        if (StringUtils.isEmpty(userCode) && StringUtils.isNotEmpty(devUserCode) && !isProductionHost()) {
            userCode = devUserCode;
        }
        // 4. JWT 用户兜底：无 Cookie 但已通过 Security 认证（本系统直接登录的场景）→ 放行，
        //    并把 JWT 里的用户同样放进 ThreadLocal，业务代码取人只有一个入口
        if (StringUtils.isEmpty(userCode)) {
            try {
                LoginUser loginUser = SecurityUtils.getLoginUser();
                if (loginUser != null && loginUser.getUser() != null) {
                    UserThreadLocal.put(loginUser.getUser());
                    return true;
                }
            } catch (Exception ignore) {
                // 未认证，走最后的拒绝
            }
        }
        // 5. 工号查用户 → ThreadLocal；查不到拒绝
        if (StringUtils.isNotEmpty(userCode)) {
            SysUser user = userService.selectUserByUserName(userCode);
            if (user != null) {
                UserThreadLocal.put(user);
                return true;
            }
        }
        ServletUtils.renderString(response,
                JSON.toJSONString(AjaxResult.error(UNAUTHORIZED_CAMSTAR, "未获取到当前登录用户")));
        return false;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        UserThreadLocal.remove();   // 必须清理，防线程池串号
    }

    /** 遍历 Cookie 取工号，命中即返回 */
    private String resolveUserCode(HttpServletRequest request) {
        Cookie[] cookies = request.getCookies();
        if (cookies == null) {
            return null;
        }
        for (Cookie cookie : cookies) {
            if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                try {
                    return new String(Base64.getDecoder().decode(cookie.getValue()));
                } catch (IllegalArgumentException e) {
                    return null;
                }
            }
        }
        return null;
    }

    private boolean isProductionHost() {
        try {
            return StringUtils.isNotEmpty(serverHostIp)
                    && serverHostIp.equals(InetAddress.getLocalHost().getHostAddress());
        } catch (Exception e) {
            return false;
        }
    }
}
```

## 1.4 芋道子系统改造（照 TFMS）

TFMS 模式：**Security 放行目标模块（免 token）+ 拦截器从 Cookie 解工号 + Controller 无 token 时兜底**。
改动清单：**新建 1 个类 + 修改 2 个文件 + 前端 3 处**。

### 1.4.1 请求要过的五道关卡（排查 401 时按这个顺序查）

| 顺序 | 关卡 | 干什么 |
|---|---|---|
| 1 | CORS 配置 | originPattern `*` + allowCredentials，跨端口带 Cookie 的前提 |
| 2 | TokenAuthenticationFilter（Security 过滤器） | 有 `Authorization: Bearer` → 查 Redis → 塞 SecurityContext；没有头则什么都不做 |
| 3 | Security 授权规则 | 静态资源 → `@PermitAll` → yaml `permit-all-urls` → 兜底 `anyRequest().authenticated()`。都不匹配且无认证 → 401 |
| 4 | CamstarInfoInterceptor（MVC 拦截器，Security 之后） | OPTIONS 放行 → 注解放行 → URL 白名单放行 → **Cookie 解码工号 → ThreadLocal** → Bearer 回退 → 全无则拒绝 |
| 5 | Controller 取人 | `getLoginUserId()` 有值 → token 用户；为 null → 拦截器 `getUserName()`（工号）查库 |

> **Cookie 只能过拦截器（关 4），过不了 Security（关 3）**——Cookie 用户的接口必须落在 1.4.3 的放行清单里。

### 1.4.2 新建拦截器

以 TFMS 的 `CamstarInfoInterceptor` 为蓝本，修掉它的两个坑（`getUserName()` NPE、拒绝时无响应体）：

```java
package cn.xxx.module.infra.framework.web.config;   // 换成本工程实际包

import cn.xxx.framework.common.pojo.CommonResult;
import cn.xxx.framework.common.util.servlet.ServletUtils;

import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.lang.reflect.Method;
import java.util.Base64;
import java.util.HashMap;
import java.util.Map;

import static cn.xxx.framework.common.exception.enums.GlobalErrorCodeConstants.UNAUTHORIZED;

/**
 * 从 Cookie Nancal_Cam_SessionId(Base64工号) 识别当前登录用户（参照 TFMS）
 */
public class CamstarInfoInterceptor implements HandlerInterceptor {

    private static final ThreadLocal<Map<String, Object>> CONTEXT = new ThreadLocal<>();
    private static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 0. CORS 预检放行
        if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
            return true;
        }
        // 1. 免鉴权注解放行：本工程自定义的 @CamstarAnonymous
        if (handler instanceof HandlerMethod) {
            Method method = ((HandlerMethod) handler).getMethod();
            Class<?> clazz = method.getDeclaringClass();
            if (clazz.isAnnotationPresent(CamstarAnonymous.class)
                    || method.isAnnotationPresent(CamstarAnonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行
        String url = request.getRequestURL().toString();
        if (url.contains("login") || url.contains("get-permission-info")) {
            return passWith("token");
        }
        // 3. Cookie 解工号（命中即返回）
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                    try {
                        String userCode = new String(
                                Base64.getDecoder().decode(cookie.getValue()), "utf-8");
                        return passWith(userCode);
                    } catch (IllegalArgumentException e) {
                        break;   // 非法 Base64，走后面的 token 回退
                    }
                }
            }
        }
        // 4. 回退：带 Bearer token 的正常芋道请求也放行（兼容非门户场景）
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return passWith("token");
        }
        // 5. 无凭证：返回 401 JSON
        ServletUtils.writeJSON(response, CommonResult.error(UNAUTHORIZED));
        return false;
    }

    private boolean passWith(String userCode) {
        Map<String, Object> map = new HashMap<>();
        map.put("CamstarUserCode", userCode);
        CONTEXT.set(map);
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest req, HttpServletResponse resp,
                                Object handler, Exception ex) {
        CONTEXT.remove();
    }

    /** 业务代码统一从这里取工号；未放过上下文的路径返回 null（TFMS 原版此处会 NPE，已修） */
    public static String getUserName() {
        Map<String, Object> map = CONTEXT.get();
        return map == null ? null : String.valueOf(map.get("CamstarUserCode"));
    }
}
```

配套注解：

```java
@Documented
public @interface CamstarAnonymous {
}
```

## 1.5 Camstar / 直开型系统页面接入

适用于 **CamstarPortal（:4200）、C# MES、任何能用完整 URL 打开的现成系统**：JUMP 不改造对方代码，
**iframe 直开完整 URL + Cookie 免登**。现网实例：4200 上的 Camstar 业务页（`http://192.168.240.127:4200/Process/...`）。

### 1.5.1 JUMP 侧怎么打开（子系统无需操作，排查时了解）

```
JUMP 登录 → 门户域种 Cookie Nancal_Cam_SessionId=Base64(工号)
  （同 hostname 不同端口 → 浏览器自动共享，主路径）
点菜单 → （跨机时）后台隐藏 iframe 调 {目标站点}/camstar-cookie-bridge.html?v=Base64(工号)
  在目标机种 Cookie（尽力而为，不阻塞打开）
→ iframe 原样直开菜单登记的完整 http URL（不拼任何前缀、不经 4221）
→ 页面发出的请求带 Cookie，Camstar 侧解工号识别用户
```

JUMP 侧现成能力（不用子系统操心）：打开超时 15s 慢提示 / 60s 失败可重试；Camstar 页签关闭后进保温池（≤8 个，重开秒回）；Console 过滤 `[camstar-diag]` 可看"点击→Cookie→导航→iframe 挂载→加载完成"全链路计时，并自动区分 JUMP 侧 / Camstar 侧慢。

### 1.5.2 Camstar 侧要求清单（就这 4 条）

| # | 要求 | 怎么确认 |
|---|---|---|
| 1 | **页面完整 URL 直达** | 无痕浏览器直接开该 URL，能出业务页（不是跳登录页）即达标；SPA 必须 history 路由（URL 带 `#` 会被 JUMP 判成若依型） |
| 2 | **认 Cookie 识别用户** | 带上 Cookie 调页面所用的接口能出数据：`curl -i "http://目标/接口" -H "Cookie: Nancal_Cam_SessionId=MTYzNTg="` |
| 3 | **允许被 iframe** | `curl -sI http://目标/页面`：响应头无 `X-Frame-Options: DENY`、无 `Content-Security-Policy: frame-ancestors` |
| 4 | **跨机部署放 bridge 页** | `http://目标/camstar-cookie-bridge.html` 能访问到（返回 html 即可）。文件用 JUMP 仓库 `jonhonjump-ui/jonhonjump-ui-admin-vue2/public/camstar-cookie-bridge.html` **原样拷贝**到站点根目录，不要改内容 |

> 最常见的"接入后 iframe 里显示成对方登录页/数据全空"：就是第 2 条没满足（对方不认这个 Cookie，或工号在对方系统不存在），或跨机没放 bridge 页（第 4 条）。

### 1.5.3 报给门户管理员的登记信息

| 项 | 填什么 | 例 |
|---|---|---|
| 菜单-路由地址 | **完整 http 地址** | `http://192.168.240.127:4200/Process/ProcessManager/ProcessIndex` |
| 菜单-路由地址（不能用冒号时） | IP + `9` + 端口编码写法 | `192.168.240.12794200/Process/...` |
| 菜单-组件路径 | **必须留空** | —— |
| 系统-访问地址 | 填 MES 入口（若依型页面拼 `/#/` 用），**Camstar 直开不经它** | `http://192.168.240.127:4221` |

登记规则（JUMP 管理后台菜单登记页提示原文）：「PATH 填 Camstar 业务完整 http（iframe 直开，不经 4221）」「组件路径留空」；若门户机用 nginx 监听 4200 反代到 Camstar，填反代地址（勿填 `/camstar-` 路径）。菜单多的话支持从 4200 的 `D2_SYS_MENU` 批量导入（管理员操作）。

# 二、人员接口接入（用户同步）

JUMP 能力：**管理后台建用户时联动登记花名册，再经配置的 HTTP 接口把人员推送到子系统（自动开账号）**，也支持在 JUMP 页面直接查询/修改/删除子系统人员。

## 2.1 概念（四个词）

| 概念 | 表/载体 | 说明 |
|---|---|---|
| **门户业务系统** | `sub_system`（oauth2_client_id **非空**） | 出现在门户里的子系统，花名册挂它下面（如 MES4200） |
| **仅接口目标** | `sub_system`（oauth2_client_id **为空**） | 只作人员接口的调用目标，不进门户（如「Camstar人员管理」）。接口管理页"接入系统"弹窗里可只填名称手动新建 |
| **花名册** | `sub_system_users` | JUMP 本地表：mainUserId / subSystemId / username（=工号）/ nickname / workshopId / teamId 等 |
| **注册状态** | `sub_system_users.employee_registered` | `0` 未注册 / `1` 已注册。调「新增人员」接口成功自动置 1；对方系统手工建过人 → 手动标 1 避免重复推送；改回 0 可重推 |

花名册挂在门户系统上，推送时由操作人显式选择接口目标（两者可以不同）。

## 2.2 JUMP 侧行为（子系统侧对照检查用）

```
① 管理员在 JUMP 建用户，勾选要登记的子系统 → 纯本地事务写花名册（employee_registered=0），
   不调任何外部接口——建用户永远不会被子系统接口失败阻塞
② 外部用户管理页选花名册行 → 注册 → 选接口目标 → JUMP 逐项调「新增人员」接口
   （已置 1 的跳过；成功置 1；单项失败只记结果不断批次）
③ 日常可经接口目标直接 查询/修改/删除 子系统人员（透传型 CRUD）
```

推送字段：username→userCode、昵称、车间编号（按「车间对照」解析）、班组 code、domainNo/erpNo/cardNo。

## 2.3 子系统要提供的接口契约（http 型，推荐：零代码接入）

JUMP 按 `sub_system_api_config` 配置纯配置驱动调用（`GenericHttpEmployeeApiAdapter`），
**子系统只要按约定提供 HTTP 接口，JUMP 侧不用写代码**：

- **鉴权**：仅支持 `authType=none`（无鉴权头）。需要登录态的系统见 2.4（camstar 型）或 2.7（写专用适配器）
- **方法**：默认 POST（可配 GET；GET 时参数以 form 提出，POST 时为 JSON body）
- **参数名**：默认用 JUMP 标准参数名；不同名时在 JUMP 配 `paramMapping` 改名，如 `{"userCode":"empNo","page":"pageNo"}`
- **空值不传**：值为 null/空串的参数不会出现在请求里

### 2.3.1 五个接口

| 用途 | 请求 | 响应（默认，可配 responseMapping 改） |
|---|---|---|
| **查询（分页）** | `{"page":1,"rows":10,"userCode":"","userName":"","workshopCode":""}`（都是可选过滤条件） | `{"code":200,"data":{"total":100,"list":[{员工行}]}}`——total 默认取 `data.total`，列表默认取 `data.list` |
| **新增（必配）** | 员工字段（见 2.3.2） | `{"code":200,"msg":"..."}` |
| **修改** | 同新增 | 同上 |
| **删除** | `{"userCode":"16358"}` | 同上 |
| **班组下拉（可选）** | `{"workshopCode":"4200"}` | 列表默认取 `data`，行字段 `teamCode`/`teamName` |

### 2.3.2 员工字段（JUMP 标准参数名）

| 参数 | 含义 | 备注 |
|---|---|---|
| `userCode` | 工号 | 即 JUMP 花名册 username，唯一标识 |
| `userName` | 姓名 | |
| `workshopCode` | 车间编号 | 由「车间对照」从用户部门映射；没配对照则为空 |
| `teamCode` | 班组编码 | |
| `domainName` | 域账号 | 从主用户带出 |
| `erpNo` | ERP 工号 | 主用户多个时取第一个 |
| `cardNo` | 卡号 | 从主用户带出 |
| `onDuty` | 在职标志 | 预留，注册推送时通常为空 |

### 2.3.3 响应格式约定

- **成功判定**：默认 `code == 200`（可配 `responseMapping.successField/successValue`，如 `{"successField":"status","successValue":"0"}`）
- **失败信息**：默认取 `msg` 字段（可配 `messageField`）
- **行字段改名**：`responseMapping.fields`，如 `{"userCode":"empNo","userName":"empName"}`
- **列表/总数路径**：默认 `data.list` / `data.total`，可配 `listPath` / `totalPath`

### 2.3.4 JUMP 侧配置（接口管理页，管理员操作）

管理后台「外部系统 → 人员接口接入」：左侧目录树（目录+叶子接口），每个叶子独立配置
**用途（auth/query/create/update/delete）/ 启用 / 方法 / 完整地址 / 携带会话 Cookie 开关 / 在线测试**；
「新增」叶子 enabled=false 时，该系统不出现在用户同步的接口目标下拉里。

## 2.4 camstar 型契约（Cookie 会话鉴权）

对方系统需要登录态时用 `apiType=camstar`（`CamstarEmployeeApiAdapter`），现网实例如
「Camstar人员管理」（`http://192.168.240.125:8888`）。

**Camstar 侧要提供的东西：**

1. **SSO 登录接口**：`GET /Base/SSOLogin/SSOLoginIn?token=Base64(调用工号)`——激活会话，HTTP 200 即算成功
2. **四个人员接口**（成功 `code==200`，失败信息放 `message`）：
   - 查询 `POST /BasicData/Employee/getEmployeeInfo`，请求 `{"userCode","userName","workshopCode","page","rows"}`（都可选），响应是**顶层** `{"code":200,"total":100,"rows":[{员工行}]}`
   - 新增/修改 `POST /BasicData/Employee/addOrUpdateUser`，请求体是 **JSON 数组** `[{userCode,userName,workshopCode,teamCode,domainName,erpNo,cardNo}]`（对齐 C# `addOrUpdateUser(List<EmployeeEntity>)`）
   - 删除 `POST /BasicData/Employee/deleteEmployeeInfo`，请求 `{"userCode":"..."}`
3. **一个调用工号**（给 JUMP 当会话账号用）

**JUMP 系统级会话鉴权配置**（authConfig JSON，管理员在接口管理页填）：

```json
{
  "name": "SSO登录",
  "url": "http://192.168.240.125:8888/Base/SSOLogin/SSOLoginIn",
  "method": "GET",
  "enabled": true,
  "userCode": "调用工号",
  "cookieName": "Nancal_Cam_SessionId"
}
```

**会话机制**：

- 正常请求带 `Cookie: Nancal_Cam_SessionId = Base64(userCode)`
- 请求失败（HTTP 错误或业务 code≠200）且该接口"携带会话"且鉴权启用 → 调 `GET {SSO登录}?token=Base64(userCode)` 激活会话后**重试一次**
- 鉴权 `enabled=false` → 完全不带 Cookie、不重登
- **每个叶子接口可独立设 `withSession`**（是否携带会话 Cookie，默认携带）——无状态接口关掉会话就不会被会话过期连累

## 2.5 车间对照（workshopCode 从哪来）

`sub_system_workshop` 表维护「JUMP 部门 ↔ 子系统车间」映射（管理后台「车间对照」页维护）。
建用户登记花名册、注册推送组装字段时，都会按对照关系把用户部门翻译成车间编号——**子系统按车间编号
接收即可**；没配对照则该字段为空。需要对照时把车间清单提供给门户团队。

## 2.6 连通性验证

- 接口管理页每个叶子有**在线测试**（与真实调用一致地注入 Cookie 头）
- 系统级有**测试会话登录**、**测试连接**（ping = page 1 行查询，返回耗时+总人数）
- curl 快验（http 型）：

```bash

curl -s -X POST "http://子系统IP:端口/api/user/page" \

```

## 2.7 需要特殊鉴权怎么办（token/header 类）

通用 http 适配器目前**只支持 authType=none**。子系统接口需要特殊认证（如固定 token 头、签名）时，
在 JUMP 侧写一个专用适配器：

1. 新建类实现 `SubSystemEmployeeApi`（六个能力：page/create/update/delete/teamCombo/ping）
2. 在 `SubSystemEmployeeApiFactory.createAdapter`（目前只有 camstar/http 两个 case）加一个分支
3. 配置页 `api_type` 填新类型

参照 `CamstarEmployeeApiAdapter`（含会话保持、失败重登的完整样例）。

| 现象 | 原因 | 解决 |
|---|---|---|
| iframe 里跳到了子系统自己的登录页 | 页面不在前端白名单；或对方不认 Cookie | permission.js 白名单补上；Camstar 类系统按 1.5.2 第 2 条核 |
| 接口 401 / `未获取到当前登录用户` | 拦截器没解到 Cookie 或工号查无此人 | DevTools 确认请求带 `Nancal_Cam_SessionId`；确认用户表有此工号 |
| 芋道接口 401 但 Cookie 在 | 模块没在 permit-all 里 | yaml 放行该模块前缀，重启 |
| iframe 白屏，Console 报 X-Frame-Options | nginx/IIS 加了拒绝头 | 删掉 `X-Frame-Options` / CSP 配置 |
| 跨机打开子系统数据全空 | Cookie 没种到目标机 | 子系统站点根目录部署 `camstar-cookie-bridge.html`；同机不同端口无此问题；Console 看 `[camstar-diag]` 日志 |
| Camstar 页面开得慢 | 页面本身慢或页内接口慢 | Console `[camstar-diag]` 会自动区分 JUMP 侧 / Camstar 侧 |
| `getUserName()`/`UserThreadLocal.get()` 报空 | 白名单路径没放上下文 | 业务代码判空；或该接口移出白名单 |
| 页面能开但数据全空 | 工号查用户返回空 | 检查用户表/视图是否含该工号 |
| 用户同步下拉没有某系统 | 该系统「新增」叶子未启用 | 接口管理页启用新增接口 |
| 注册推送报"接口返回错误" | 对方响应 code≠200 或字段不符 | 看返回的 msg/message；核对 successField/successValue 配置 |
| camstar 型偶发失败后会自愈 | 会话过期触发重登重试一次 | 正常机制；频繁出现检查 SSO 登录接口稳定性 |
| 建用户失败提示花名册占用 | 同 (系统,工号) 已绑其他主用户 | 先在花名册解绑/删除旧行，再建用户 |
