## 使用说明

本手册面向子系统侧，仅描述**子系统需要完成的工作和需要提供的资料**。JUMP 侧工作（系统登记、菜单登记、接口配置、花名册管理）由门户管理员在管理后台完成，子系统只需按各章末尾"交付物"要求提交资料。

接入 JUMP 分为三个相互独立的方面：

| 方面 | 内容 | 是否必做 |
|---|---|---|
| ① 页面挂菜单 | 子系统页面以免登录方式嵌入门户 | **必做** |
| ② 人员同步接口 | 门户创建用户后自动在子系统开通账号 | 按需 |
| ③ 反向调用 JUMP | 子系统调用 JUMP（机端刷卡、读取权限等） | 可选 |

## 1.2 通用接入前提

| # | 前提条件 | 说明 |
|---|---|---|
| 1 | **工号体系统一** | JUMP 以工号（username）作为用户唯一标识；子系统必须能按工号检索本系统用户，否则页面可打开但数据为空 |
| 2 | **支持 Cookie `Nancal_Cam_SessionId` 识别用户** | Cookie 值 = `Base64(UTF-8(工号))`。用户登录 JUMP 后自动写入（同 hostname 不同端口场景浏览器自动共享），子系统后端解码该 Cookie 获取当前用户工号 |

Cookie 值自测方法（Git Bash）：

```bash
printf '16358' | base64    # 输出 MTYzNTg=，即工号 16358 对应的 Cookie 值
```

# 第二章 页面接入（免登录）

## 2.1 认证机制

用户登录 JUMP 后，门户前端立即写入身份 Cookie；门户打开子系统页面的链路中**不存在 OAuth 跳转**（历史版本文档中"带 `#` 走 OAuth"的说明已废止）。完整链路如下：

```
JUMP 登录（工号）
  → 前端写入 Cookie：Nancal_Cam_SessionId = Base64UTF8(工号)，path=/
  → 点击子系统菜单 → iframe 打开（同 hostname 不同端口时 Cookie 自动共享；
    跨机部署时由门户后台隐藏 iframe 调用子系统站点的 camstar-cookie-bridge.html 写入 Cookie，不阻塞页面打开）
  → 子系统后端解码 Cookie → 得到工号 → 作为"当前用户"
```

**OAuth 访问方式在当前程序中的现状**（按代码核实）：

| 层面 | 现状 |
|---|---|
| 后端授权码端点 | **保留且可用**：`OAuth2OpenController`（`/system/oauth2`）提供 `GET/POST /authorize`（授权码模式授权）与 `POST /token`（@PermitAll，授权码换取访问令牌） |
| 子系统列表下发 | `SubSystemUsersServiceImpl.buildSsoUrl` 为每个门户业务系统生成 `/sso?client_id=..&response_type=code&scope=..` 授权链接（scope 取 client 的 autoApproveScopes / scopes，缺省 user.read），随 `/system/sub-system-users/my-list` 响应的 `ssoUrl` 字段下发——字段仍在下发，门户前端未消费 |
| 门户前端 | **业务页一律 Cookie iframe 直开，不走 OAuth**（`permission.js` 注释原文："门户业务页一律 Cookie iframe 直开，不再走 OAuth/SSO 等待。kind=ruoyi 只表示 iframe URL 用 /#/ 形态，鉴权仍是 Nancal_Cam_SessionId"）；门户前端已无 `/sso` 授权页（`portalRoute.js` 公开路径白名单中的 `/sso` 为历史残留） |
| 子系统 SDK | `PortalOAuthClient` 能力完整：`buildAuthorizeUrl()` 生成 `{portalUrl}/sso?...&response_type=code` 跳转地址、`exchangeCodeForToken(code)` 调 `POST /system/oauth2/token` 换令牌；但**授权码跳转依赖门户提供 `/sso` 授权页，当前门户前端未提供** |

结论：OAuth 的服务端部分（token 端点、SDK 封装、机端刷卡、外部系统登记绑定）在程序中均可用；**浏览器授权码跳转这半条链路门户前端已不承接**。若现场需要以 OAuth 跳转方式访问子系统（例如子系统要求独立登录回调而非 iframe 嵌入），需先在门户侧补建 `/sso` 授权页（可参照芋道原版 `sso.vue` 恢复），并与门户团队确认启用范围。

## 2.2 菜单接入类型

菜单类型由 JUMP 侧登记信息决定（判定逻辑的权威实现为门户前端 `utils/portalMenuKind.js`）：

| 类型 | 登记方式 | 打开方式 | 对子系统的要求 |
|---|---|---|---|
| **直开型**（Camstar/外链） | 路由地址填写**完整 http 地址**（如 `http://192.168.240.127:4200/Process/...`），组件路径**留空** | iframe 直接打开该 URL | 页面须支持完整 URL 直达（**history 路由**；URL 含 `#` 会被判定为若依型） |
| **若依型** | 组件路径填写 `system/xxx`（或路由地址带 `#`） | iframe 打开 `{systemUrl}/#/{路由}`，菜单树由 JUMP 门户渲染 | hash 路由即可；页面接口鉴权依赖 Cookie |

## 2.3 通用接入条件核查（4 项）

| # | 检查项 | 核查方法 / 参照 |
|---|---|---|
| 1 | **直开型必须为 history 路由**（URL 不含 `#`） | 参照：4200 `vue4200/src/router/index.js:935`、TFMS `ui/src/router/index.js:458`，均为 `mode: 'history'` |
| 2 | **工号体系统一** | 解码 Cookie 得到的工号，子系统能检索到对应用户（本库用户表 / 工号字段 / 员工视图） |
| 3 | **部署形态确认** | 同 hostname 不同端口 = Cookie 自动共享，无需额外工作；跨机部署**推荐经门户机 Nginx 反向代理**实现同域访问（见 2.7）；未经反代直连跨机地址时，子系统站点根目录需部署 `camstar-cookie-bridge.html`（见 2.6.2 第 4 项） |
| 4 | **响应头不拒绝 iframe** | 框架默认已放行：4200 `SecurityConfig.java:135`、TFMS `MesWebSecurityConfigurerAdapter.java:117` 均已配置 `frameOptions().disable()`；若前置 nginx，需确认未配置 `X-Frame-Options DENY` / CSP |

### 2.4.3 新建 `framework/interceptor/CamstarInfoInterceptor.java`

```java
package com.ruoyi.framework.interceptor;   // ← 替换为本工程实际包路径

import com.alibaba.fastjson2.JSON;
import com.ruoyi.common.annotation.Anonymous;
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.common.core.domain.entity.SysUser;
import com.ruoyi.common.utils.StringUtils;
import com.ruoyi.common.utils.SecurityUtils;
import com.ruoyi.common.utils.servlet.ServletUtils;
import com.ruoyi.framework.security.LoginUser;
import com.ruoyi.system.service.ISysUserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.net.InetAddress;
import java.util.Base64;
import java.util.List;

/**
 * 从 Cookie Nancal_Cam_SessionId（Base64 工号）识别当前登录用户。
 * 模板来源：ruoyi4200 同名类，已修正白名单配置化 / Cookie 命中即返回 / 401 响应体三个问题。
 */
@Component
public class CamstarInfoInterceptor implements HandlerInterceptor {

    public static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";
    /** 业务错误码：前端据此识别"门户身份失效" */
    public static final int UNAUTHORIZED_CAMSTAR = 4001;

    @Autowired
    private ISysUserService userService;

    /** 白名单 uri（contains 匹配）：本系统无需识别用户的接口 */
    @Value("#{'${camstar.whitelist:}'.split(',')}")
    private List<String> whitelist;

    /** 生产服务器 IP：非此 IP 视为开发环境 */
    @Value("${camstar.server-host-ip:}")
    private String serverHostIp;

    /** 开发环境测试工号 */
    @Value("${camstar.dev-user-code:}")
    private String devUserCode;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 1. 标注 @Anonymous（若依自带）的接口放行
        if (handler instanceof HandlerMethod) {
            HandlerMethod hm = (HandlerMethod) handler;
            if (hm.hasMethodAnnotation(Anonymous.class)
                    || hm.getBeanType().isAnnotationPresent(Anonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行
        String uri = request.getRequestURI();
        if (whitelist != null && whitelist.stream().anyMatch(u -> !u.isEmpty() && uri.contains(u))) {
            return true;
        }
        // 3. 开发环境兜底：非生产 IP 使用测试工号
        String userCode = resolveUserCode(request);
        if (StringUtils.isEmpty(userCode) && StringUtils.isNotEmpty(devUserCode) && !isProductionHost()) {
            userCode = devUserCode;
        }
        // 4. JWT 用户兜底：无 Cookie 但已通过 Security 认证（本系统直接登录的场景）→ 放行，
        //    并将 JWT 中的用户同样放入 ThreadLocal，保证业务代码取人只有一个入口
        if (StringUtils.isEmpty(userCode)) {
            try {
                LoginUser loginUser = SecurityUtils.getLoginUser();
                if (loginUser != null && loginUser.getUser() != null) {
                    UserThreadLocal.put(loginUser.getUser());
                    return true;
                }
            } catch (Exception ignore) {
                // 未认证，走最后的拒绝逻辑
            }
        }
        // 5. 工号查用户 → ThreadLocal；查不到则拒绝
        if (StringUtils.isNotEmpty(userCode)) {
            SysUser user = userService.selectUserByUserName(userCode);
            if (user != null) {
                UserThreadLocal.put(user);
                return true;
            }
        }
        ServletUtils.renderString(response,
                JSON.toJSONString(AjaxResult.error(UNAUTHORIZED_CAMSTAR, "未获取到当前登录用户")));
        return false;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        UserThreadLocal.remove();   // 必须清理，防止线程池复用导致上下文串用
    }

    /** 遍历 Cookie 取工号，命中即返回 */
    private String resolveUserCode(HttpServletRequest request) {
        Cookie[] cookies = request.getCookies();
        if (cookies == null) {
            return null;
        }
        for (Cookie cookie : cookies) {
            if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                try {
                    return new String(Base64.getDecoder().decode(cookie.getValue()));
                } catch (IllegalArgumentException e) {
                    return null;
                }
            }
        }
        return null;
    }

    private boolean isProductionHost() {
        try {
            return StringUtils.isNotEmpty(serverHostIp)
                    && serverHostIp.equals(InetAddress.getLocalHost().getHostAddress());
        } catch (Exception e) {
            return false;
        }
    }
}
```

业务代码获取当前用户：

```java
SysUser currentUser = UserThreadLocal.get();
String userCode = currentUser.getUserName();   // 即工号
```

> **注解版本适配说明（老版本若依必读）**
>
> 模板第 1 步"注解放行"引用的 `@Anonymous` 是标准若依 4.7+ 官方自带注解（`com.ruoyi.common.annotation.Anonymous`）。
> 它一次标注、两层生效：启动时 `PermitAllUrlProperties` 扫描所有标注该注解的接口 → 将 URL 注册进 SecurityConfig
> 的 `permitAll()`（Security 层免 token）；同时拦截器见注解直接放行（Cookie 层免校验）。请求到达 Controller 前的
> 关卡顺序为：**① Security 过滤器（验 token）→ ② 拦截器（验 Cookie）**，两层均放行后接口才能无凭证调通。
>
> 4200 参照工程基于老版本若依（当时尚无官方 `@Anonymous`），自建了同用途的 `@CamStarAnonymous` 注解及配套扫描类。
>
> **若本工程为老版本若依**（工程中不存在 `com.ruoyi.common.annotation.Anonymous` 类，模板编译报错）：
> 1. 从 4200 参照工程复制 `@CamStarAnonymous` 注解类**及其配套的 `PermitAllUrlProperties`**（两者必须一起复制：
>    注解本身只是标记，仅复制注解则 Security 层不会放行，请求在进入拦截器前即被 Security 以 401 拒绝）；
> 2. 将模板 2.4.3 中的 `import com.ruoyi.common.annotation.Anonymous;` 及两处 `Anonymous.class` 替换为 `CamStarAnonymous`；
> 3. 将 2.4.5 中 Controller 上的 `@Anonymous` 同样替换为 `@CamStarAnonymous`。

## 2.5 路径 B：芋道框架子系统改造指引

**参照工程：`TFMS-master/tfms`。** 实施模式：**Security 放行目标模块（免 token）+ 拦截器从 Cookie 解码工号 + Controller 无 token 时兜底取人**。

改造范围总览：

| # | 改造项 | 详见 |
|---|---|---|
| 1 | 新建 `CamstarInfoInterceptor` + `@CamstarAnonymous` 注解（OPTIONS/注解/白名单放行 → Cookie 解码工号 → Bearer 回退 → 401 JSON） | 2.5.2 |
| 2 | WebMvcConfigurer 注册拦截器 `/**` | 2.5.3 |
| 3 | `application.yaml` 的 `permit-all-urls` 放行需挂接 JUMP 的模块前缀（如 `/admin-api/tool/**`）——Cookie 无法通过 Security，必须依赖此项 | 2.5.4 |
| 4 | Controller 双通道取人：`getLoginUserId()` 有值走 token，为空时用拦截器工号查库 | 2.5.5 |
| 5 | 前端 3 处：`withCredentials: true`、路由白名单（hash 路由可保留） | 2.5.6 |

### 2.5.1 请求处理链路（排查 401 时按此顺序检查）

| 顺序 | 环节 | 职责 |
|---|---|---|
| 1 | CORS 配置 | originPattern `*` + allowCredentials，跨端口携带 Cookie 的前提 |
| 2 | TokenAuthenticationFilter（Security 过滤器） | 有 `Authorization: Bearer` → 查 Redis → 写入 SecurityContext；无该请求头则不做任何处理 |
| 3 | Security 授权规则 | 静态资源 → `@PermitAll` → yaml `permit-all-urls` → 兜底 `anyRequest().authenticated()`。均不匹配且无认证 → 401 |
| 4 | CamstarInfoInterceptor（MVC 拦截器，Security 之后） | OPTIONS 放行 → 注解放行 → URL 白名单放行 → **Cookie 解码工号 → ThreadLocal** → Bearer 回退 → 全无则拒绝 |
| 5 | Controller 取人 | `getLoginUserId()` 有值 → token 用户；为 null → 拦截器 `getUserName()`（工号）查库 |

> **Cookie 只能通过拦截器（环节 4），无法通过 Security（环节 3）**——Cookie 用户的接口必须落在 2.5.4 的放行清单内。

### 2.5.2 新建拦截器与注解

以下模板已修正参照实现（TFMS）的两个已知问题（`getUserName()` 空指针、拒绝时无响应体），可直接复制后替换其中标注「← 替换为本工程实际包路径」的占位内容使用：

```java
package cn.xxx.module.infra.framework.web.config;   // ← 替换为本工程实际包路径

import cn.xxx.framework.common.pojo.CommonResult;            // ← 替换为本工程实际包路径
import cn.xxx.framework.common.util.servlet.ServletUtils;    // ← 替换为本工程实际包路径

import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.lang.reflect.Method;
import java.util.Base64;
import java.util.HashMap;
import java.util.Map;

import static cn.xxx.framework.common.exception.enums.GlobalErrorCodeConstants.UNAUTHORIZED;   // ← 替换为本工程实际包路径

/**
 * 从 Cookie Nancal_Cam_SessionId（Base64 工号）识别当前登录用户。
 * 模板来源：TFMS 同名类，已修正 getUserName() 空指针 / 拒绝时无响应体两个问题。
 */
public class CamstarInfoInterceptor implements HandlerInterceptor {

    private static final ThreadLocal<Map<String, Object>> CONTEXT = new ThreadLocal<>();
    private static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 0. CORS 预检放行
        if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
            return true;
        }
        // 1. 免鉴权注解放行：本工程自定义的 @CamstarAnonymous
        if (handler instanceof HandlerMethod) {
            Method method = ((HandlerMethod) handler).getMethod();
            Class<?> clazz = method.getDeclaringClass();
            if (clazz.isAnnotationPresent(CamstarAnonymous.class)
                    || method.isAnnotationPresent(CamstarAnonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行（← 按本工程实际放行地址调整）
        String url = request.getRequestURL().toString();
        if (url.contains("login") || url.contains("get-permission-info")) {
            return passWith("token");
        }
        // 3. Cookie 解码工号（命中即返回）
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                    try {
                        String userCode = new String(
                                Base64.getDecoder().decode(cookie.getValue()), "utf-8");
                        return passWith(userCode);
                    } catch (IllegalArgumentException e) {
                        break;   // 非法 Base64，走后续 token 回退
                    }
                }
            }
        }
        // 4. 回退：携带 Bearer token 的正常芋道请求同样放行（兼容非门户场景）
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return passWith("token");
        }
        // 5. 无凭证：返回 401 JSON
        ServletUtils.writeJSON(response, CommonResult.error(UNAUTHORIZED));
        return false;
    }

    private boolean passWith(String userCode) {
        Map<String, Object> map = new HashMap<>();
        map.put("CamstarUserCode", userCode);
        CONTEXT.set(map);
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest req, HttpServletResponse resp,
                                Object handler, Exception ex) {
        CONTEXT.remove();
    }

    /** 业务代码统一从此处取工号；未写入上下文的路径返回 null */
    public static String getUserName() {
        Map<String, Object> map = CONTEXT.get();
        return map == null ? null : String.valueOf(map.get("CamstarUserCode"));
    }
}
```

## 2.6 路径 C：Camstar 及外部系统页面接入

适用于 **CamstarPortal（:4200）、C# MES 及任何可通过完整 URL 访问的现成系统**：JUMP 不改造对方代码，采用 **iframe 直开完整 URL + Cookie 免登录** 方式。现网实例：4200 上的 Camstar 业务页（`http://192.168.240.127:4200/Process/...`）。

### 2.6.1 JUMP 侧处理流程（子系统无需实施，供排查时了解）

```
JUMP 登录 → 门户域写入 Cookie Nancal_Cam_SessionId=Base64(工号)
  （同 hostname 不同端口 → 浏览器自动共享，主路径）
点击菜单 → （跨机部署时）后台隐藏 iframe 调用 {目标站点}/camstar-cookie-bridge.html?v=Base64(工号)
  在目标机写入 Cookie（尽力而为，不阻塞打开）
→ iframe 按菜单登记的完整 http URL 原样直开（不拼接任何前缀、不经过 4221）
→ 页面发起的请求携带 Cookie，Camstar 侧解码工号识别用户
```

JUMP 侧已具备的能力（子系统无需关注）：打开超时 15 秒慢提示 / 60 秒失败可重试；Camstar 页签关闭后进入保温池（≤8 个，重开即时恢复）；浏览器 Console 过滤 `[camstar-diag]` 可查看"点击 → Cookie → 导航 → iframe 挂载 → 加载完成"全链路计时，并自动区分 JUMP 侧 / Camstar 侧耗时。

### 2.6.2 子系统侧要求（共 4 项）

| # | 要求 | 不满足的后果 / 核查方法 |
|---|---|---|
| 1 | **页面完整 URL 直达** | 无痕浏览器直接访问该 URL，能打开业务页（而非跳转登录页）即达标；SPA 必须为 history 路由（URL 含 `#` 会被 JUMP 判定为若依型）。不满足时会被判定为若依型或打开后跳转对方登录页 |
| 2 | **通过 Cookie 识别用户**（Camstar 体系原生使用该 Cookie，现网零改造） | 携带 Cookie 调用页面所用接口能返回数据：`curl -i "http://目标/接口" -H "Cookie: Nancal_Cam_SessionId=MTYzNTg="`。不满足时页面可打开但数据为空或跳转登录页 |
| 3 | **允许被 iframe 嵌入** | `curl -sI http://目标/页面`：响应头无 `X-Frame-Options: DENY`、无 `Content-Security-Policy: frame-ancestors`。不满足时 iframe 白屏 |
| 4 | **跨机部署时部署 bridge 页**（经门户机 Nginx 反代访问时无需此项，见 2.7；与 JUMP 同机不同端口部署时亦无需） | `http://目标/camstar-cookie-bridge.html` 可访问（返回 html 即可）。文件取自 JUMP 仓库 `jonhonjump-ui/jonhonjump-ui-admin-vue2/public/camstar-cookie-bridge.html`，**原样拷贝**至站点根目录，不得修改内容。不满足时 Cookie 无法写入目标机，数据为空 |

> 最高频故障"接入后 iframe 内显示对方登录页 / 数据为空"：原因为第 2 项不满足（对方系统不识别该 Cookie，或工号在对方系统中不存在），或跨机部署未部署 bridge 页（第 4 项）。

## 2.7 跨机部署统一方案：门户机 Nginx 反向代理（推荐）

JUMP 与各子系统不在同一台服务器时，**推荐在门户机部署 Nginx，将各子系统反向代理为门户机同一 hostname 下的不同端口**：浏览器侧统一访问 `http://门户机IP:{反代端口}`，与门户同 hostname → 身份 Cookie 自动共享，跨机问题在部署层面转化为"同机不同端口"形态，子系统无需部署 bridge 页。现网门户机为 `192.168.240.129`，完整配置文件：`doc/nginx.conf`（本节模板与其保持一致，复制后替换 IP 与端口即可）。

三类子系统的反代差异一览：

| 子系统类型 | server 块结构 | 关键点 |
|---|---|---|
| Camstar / 直开型 | 单 location `/` 整站反代 | `proxy_set_header Host` 填子系统真实地址；`proxy_redirect` 改写跳转地址 |
| 若依 | `/`（前端）+ `^~ /prod-api/`（后端） | 后端 proxy_pass **带尾斜杠** = 剥掉 `/prod-api` 前缀；不带 = 保留（以后端部署为准） |
| 芋道 | `/`（前端）+ `^~ /admin-api/`（后端）+ WebSocket location | 后端 proxy_pass **不带尾斜杠**（保留 `/admin-api` 前缀）；WebSocket 必须带升级头 |

### 2.7.2 Camstar / 直开型子系统（单 location 整站反代）

```nginx
### 制造二部 Camstar MES
server {
    listen 4200;                                       # ← 门户机反代端口（菜单登记即用该端口）
    server_name 192.168.240.129;                       # ← 门户机 IP

    location / {
        proxy_pass http://192.168.240.127:4200/;       # ← 子系统真实地址
        proxy_set_header Host 192.168.240.127:4200;    # ← 填子系统真实地址（对方校验 Host 时必须真实值）
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_redirect http://192.168.240.127:4200/ /; # ← 后端跳转地址改写回反代地址
    }
}
```

要点：整站仅一个 location；`proxy_set_header Host` 必须填子系统真实 IP:端口（Camstar 侧存在 Host 校验，填反代地址会导致回话校验失败）；`proxy_redirect` 将响应 `Location` 头中的绝对地址改写为反代地址，否则页面跳转会绕过反代直连真实地址。

### 2.7.3 若依子系统（前端 + /prod-api/ 后端两段反代）

```nginx
### 制造二部 ruoyi MES
server {
    client_max_body_size 100M;                         # ← 按上传需求
    listen 4221;                                       # ← 门户机反代端口
    server_name 192.168.240.129;

    # 前端
    location / {
        proxy_pass http://192.168.240.127:4221/;       # ← 子系统前端真实地址
        proxy_set_header Host 192.168.240.127:4221;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_redirect http://192.168.240.127:4221/ /;
    }

    # 后端：proxy_pass 带尾斜杠 → /prod-api/ 前缀被替换为 /
    location ^~ /prod-api/ {
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header REMOTE-HOST $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass http://192.168.240.127:4222/;       # ← 子系统后端真实地址
        proxy_pass_request_headers on;
    }
}
```

**尾斜杠说明（关键，配置错误将导致接口 404）：**

| proxy_pass 写法 | 转发效果 | 适用后端 |
|---|---|---|
| `http://IP:端口/;`（**带尾斜杠**） | `/prod-api/system/user` → 后端收到 `/system/user`，前缀被剥掉 | 后端无 context-path（标准若依打包） |
| `http://IP:端口;`（**不带尾斜杠**） | 前缀原样保留，后端收到 `/prod-api/system/user` | 后端配置了 `context-path=/prod-api` |

现网两种写法并存：4221 / 4316 / 4400 / 3500 / 5677 为带尾斜杠剥前缀；9100 为不带尾斜杠保留前缀。配置时以后端实际部署方式为准。

```nginx
        proxy_pass http://192.168.240.129:12345/admin-api/;   # ← 门户后端（保留 /admin-api 前缀）
    }
}
```

（同机独立应用亦可参照此写法：前端本地目录 + 后端 `/admin-api/` 反代，现网 9000 端口的柜机系统即为此形态。）

### 2.7.7 配置与登记要点

1. **菜单登记填写反代地址**：`http://门户机IP:{监听端口}/...`（如 `http://192.168.240.129:4200/Process/...`），不得填写子系统真实地址；Camstar 直开勿填 `/camstar-` 路径（同 2.6.3）。
2. 经反代后浏览器与子系统同 hostname → Cookie 自动共享，**子系统无需部署 bridge 页**；仅当菜单登记为子系统真实跨机地址（未经反代）时，才需要 bridge 页（2.6.2 第 4 项兜底）。
3. 人员同步接口配置的 baseUrl 同理优先填写反代地址（如 `http://192.168.240.129:8888`），门户机到子系统真实地址的网络由 Nginx 打通。
4. 新增子系统 = 在 `nginx.conf` 增加一个 server 块（按 2.7.2 ~ 2.7.4 对应类型复制模板）+ `nginx -s reload` 生效；端口分配遵循现网规划（2.7.6），避免与已有监听冲突。
5. 排查手段：`logs/access.log` 已含 `upstream=` 与 `resp=` 字段，可直接定位"请求打到哪个后端、耗时多少"；浏览器 Console 过滤 `[camstar-diag]`（见 2.6.1）可区分门户侧 / 子系统侧耗时。

# 第三章 人员同步接口接入（用户同步）

## 3.1 功能概述

JUMP 能力：**管理后台创建用户时联动登记花名册，再经配置的 HTTP 接口将人员推送到子系统（自动开通账号）**；同时支持在 JUMP 页面直接查询 / 修改 / 删除子系统人员。

## 3.2 术语与数据模型

| 概念 | 表/载体 | 说明 |
|---|---|---|
| **门户业务系统** | `sub_system`（oauth2_client_id **非空**） | 出现在门户中的子系统，花名册隶属于该系统（如 MES4200） |
| **仅接口目标** | `sub_system`（oauth2_client_id **为空**） | 仅作为人员接口的调用目标，不进入门户（如「Camstar人员管理」）。接口管理页"接入系统"弹窗支持仅填名称手动新建 |
| **花名册** | `sub_system_users` | JUMP 本地表：mainUserId / subSystemId / username（=工号）/ nickname / workshopId / teamId 等 |
| **注册状态** | `sub_system_users.employee_registered` | `0` 未注册 / `1` 已注册。调用「新增人员」接口成功后自动置 1；对方系统已手工建人的记录应手动置 1 以避免重复推送；改回 0 可重新推送 |

花名册挂接在门户业务系统上，推送时由操作人显式选择接口目标（两者可以不同）。

## 3.3 JUMP 侧处理流程（子系统侧对照检查用）

```
① 管理员在 JUMP 创建用户，勾选需登记的子系统 → 纯本地事务写入花名册（employee_registered=0），
   不调用任何外部接口——创建用户操作不会被子系统接口失败阻塞
② 外部用户管理页选择花名册记录 → 注册 → 选择接口目标 → JUMP 逐项调用「新增人员」接口
   （已置 1 的跳过；成功置 1；单项失败仅记录结果，不中断批次）
③ 日常可经接口目标直接 查询/修改/删除 子系统人员（透传型 CRUD）
```

推送字段：username→userCode、昵称、车间编号（按「车间对照」解析）、班组 code、domainNo/erpNo/cardNo。

## 3.4 接口契约：HTTP 通用型（推荐，零代码接入）

JUMP 按 `sub_system_api_config` 配置纯配置化调用（`GenericHttpEmployeeApiAdapter`），**子系统只需按以下约定提供 HTTP 接口，JUMP 侧无需开发代码**：

- **鉴权**：仅支持 `authType=none`（无鉴权头）。需要登录态的系统见 3.5（camstar 型）或 3.8（专用适配器）
- **请求方法**：默认 POST（可配置为 GET；GET 时参数以 form 方式提交，POST 时为 JSON body）
- **参数名**：默认使用 JUMP 标准参数名；不一致时由 JUMP 侧配置 `paramMapping` 改名，如 `{"userCode":"empNo","page":"pageNo"}`
- **空值处理**：值为 null/空串的参数不会出现在请求中

### 3.4.1 接口清单（5 个）

| 用途 | 请求 | 响应（默认格式，可配 responseMapping 调整） |
|---|---|---|
| **查询（分页）** | `{"page":1,"rows":10,"userCode":"","userName":"","workshopCode":""}`（均为可选过滤条件） | `{"code":200,"data":{"total":100,"list":[{员工行}]}}`——total 默认取 `data.total`，列表默认取 `data.list` |
| **新增（必配）** | 员工字段（见 3.4.2） | `{"code":200,"msg":"..."}` |
| **修改** | 同新增 | 同上 |
| **删除** | `{"userCode":"16358"}` | 同上 |
| **班组下拉（可选）** | `{"workshopCode":"4200"}` | 列表默认取 `data`，行字段 `teamCode`/`teamName` |

### 3.4.2 员工字段（JUMP 标准参数名）

| 参数 | 含义 | 备注 |
|---|---|---|
| `userCode` | 工号 | 即 JUMP 花名册 username，唯一标识 |
| `userName` | 姓名 | |
| `workshopCode` | 车间编号 | 由「车间对照」从用户部门映射；未配置对照则为空 |
| `teamCode` | 班组编码 | |
| `domainName` | 域账号 | 从主用户带出 |
| `erpNo` | ERP 工号 | 主用户多个时取第一个 |
| `cardNo` | 卡号 | 从主用户带出 |
| `onDuty` | 在职标志 | 预留，注册推送时通常为空 |

### 3.4.3 响应格式约定

- **成功判定**：默认 `code == 200`（可配置 `responseMapping.successField/successValue`，如 `{"successField":"status","successValue":"0"}`）
- **失败信息**：默认取 `msg` 字段（可配置 `messageField`）
- **行字段改名**：`responseMapping.fields`，如 `{"userCode":"empNo","userName":"empName"}`
- **列表/总数路径**：默认 `data.list` / `data.total`，可配置 `listPath` / `totalPath`

### 3.4.4 JUMP 侧配置说明（接口管理页，管理员操作）

管理后台「外部系统 → 人员接口接入」：左侧目录树（目录 + 叶子接口），每个叶子独立配置
**用途（auth/query/create/update/delete）/ 启用 / 方法 / 完整地址 / 携带会话 Cookie 开关 / 在线测试**；
「新增」叶子 enabled=false 时，该系统不出现在用户同步的接口目标下拉中。

## 3.5 接口契约：Camstar 会话型（Cookie 会话鉴权）

对方系统需要登录态时使用 `apiType=camstar`（`CamstarEmployeeApiAdapter`），现网实例如「Camstar人员管理」（`http://192.168.240.125:8888`）。

**子系统（Camstar）侧需提供：**

1. **SSO 登录接口**：`GET /Base/SSOLogin/SSOLoginIn?token=Base64(调用工号)`——用于激活会话，HTTP 200 即视为成功（若人员接口本身无需登录态，可省略）
2. **四个人员接口**（成功 `code==200`，失败信息放 `message`）：
   - 查询 `POST /BasicData/Employee/getEmployeeInfo`，请求 `{"userCode","userName","workshopCode","page","rows"}`（均可选），响应为**顶层** `{"code":200,"total":100,"rows":[{员工行}]}`
   - 新增/修改 `POST /BasicData/Employee/addOrUpdateUser`，请求体为 **JSON 数组** `[{userCode,userName,workshopCode,teamCode,domainName,erpNo,cardNo}]`（对齐 C# `addOrUpdateUser(List<EmployeeEntity>)`）
   - 删除 `POST /BasicData/Employee/deleteEmployeeInfo`，请求 `{"userCode":"..."}`
3. **一个调用工号**（供 JUMP 作为会话账号使用）

**JUMP 系统级会话鉴权配置**（authConfig JSON，管理员在接口管理页填写）：

```json
{
  "name": "SSO登录",
  "url": "http://192.168.240.125:8888/Base/SSOLogin/SSOLoginIn",
  "method": "GET",
  "enabled": true,
  "userCode": "调用工号",
  "cookieName": "Nancal_Cam_SessionId"
}
```

**会话机制：**

- 正常请求携带 `Cookie: Nancal_Cam_SessionId = Base64(userCode)`
- 请求失败（HTTP 错误或业务 code≠200）且该接口"携带会话"且鉴权启用时 → 调用 `GET {SSO登录}?token=Base64(userCode)` 激活会话后**重试一次**
- 鉴权 `enabled=false` 时 → 完全不携带 Cookie、不重新登录
- **每个叶子接口可独立设置 `withSession`**（是否携带会话 Cookie，默认携带）——无状态接口关闭会话后不受会话过期影响

## 3.6 车间编号对照（workshopCode 来源）

`sub_system_workshop` 表维护「JUMP 部门 ↔ 子系统车间」映射（管理后台「车间对照」页维护）。
创建用户登记花名册、注册推送组装字段时，均按对照关系将用户部门转换为车间编号——**子系统按车间编号
接收即可**；未配置对照时该字段为空。需要对照时，将车间清单提供给门户团队配置。

## 3.7 连通性验证

- 接口管理页每个叶子均提供**在线测试**（与真实调用一致地注入 Cookie 头）
- 系统级提供**测试会话登录**、**测试连接**（ping = page 1 行查询，返回耗时 + 总人数）
- curl 快速验证（http 型）：

```bash

# 查询 → 期望 {"code":200,"data":{"total":N,"list":[...]}}
curl -s -X POST "http://子系统IP:端口/api/user/page" \
  -H "Content-Type: application/json" -d '{"page":1,"rows":1}'

# 新增 → 期望 {"code":200}
curl -s -X POST "http://子系统IP:端口/api/user/create" \
  -H "Content-Type: application/json" \

```

## 3.8 特殊鉴权扩展（token / header 类）

通用 HTTP 适配器目前**仅支持 authType=none**。子系统接口需要特殊认证（如固定 token 头、签名）时，
需在 JUMP 侧开发专用适配器：

1. 新建类实现 `SubSystemEmployeeApi`（六个能力：page/create/update/delete/teamCombo/ping）
2. 在 `SubSystemEmployeeApiFactory.createAdapter`（目前仅 camstar/http 两个分支）增加一个分支
3. 配置页 `api_type` 填写新类型

参照实现：`CamstarEmployeeApiAdapter`（含会话保持、失败重登的完整样例）。

# 第四章 反向调用 JUMP（可选）

## 4.1 客户端 SDK

引入 JUMP 提供的 `jonhonjump-framework/portal-subsystem-client`。配置项 `portal.subsystem.*`
（clientId / clientSecret / apiUrl / read-mode=redis 等，见 `PortalSubSystemProperties`）。
SDK 请求自动携带 `Authorization: Bearer {accessToken}` 或 `Basic Base64(clientId:clientSecret)` + `tenant-id` 头。

其中 OAuth 客户端（`PortalOAuthClient`）提供授权码模式封装：`buildAuthorizeUrl()` 生成
`{portalUrl}/sso?client_id=..&response_type=code&scope=..&state=..` 跳转地址，`exchangeCodeForToken(code)`
经 `POST /system/oauth2/token` 换取访问令牌（Basic 认证）。注意：该跳转依赖门户提供 `/sso` 授权页，
当前门户前端未提供此页面（见 2.1 的 OAuth 现状说明）——采用 OAuth 跳转方式前需与门户团队确认。

## 4.2 设备通道：机端刷卡 / 权限拉取（无用户 Token）

`POST /system/oauth2/subsystem/v1/card-login`、`/permission-info`（`@PermitAll`，clientSecret 通过
HTTP Basic 或 body 传递）——凭花名册校验并下发角色 / 菜单 / 权限。

## 4.3 权限包直读 Redis（高性能读取）

`/system/oauth2/subsystem/redis/v1/**`（需 scope `user.read`）：上下文读取 / 重建 / evict、扩展缓存代写。
Redis Key：`portal:perm:context:{username}:{clientId}`；RBAC 版本 `portal_rbac_version:{subSystemId}`。
菜单 / 角色变更依赖 evict，子系统缓存 miss 时提示用户重新登录。

# 第五章 常见问题排查

| 现象 | 原因 | 解决方法 |
|---|---|---|
| iframe 内跳转至子系统自身登录页 | 页面不在前端白名单；或对方系统不识别 Cookie | permission.js 白名单补充该页面；Camstar 类系统按 2.6.2 第 2 项核查 |
| 接口 401 / `未获取到当前登录用户` | 拦截器未解到 Cookie 或工号查无此人 | DevTools 确认请求携带 `Nancal_Cam_SessionId`；确认用户表存在该工号 |
| 芋道接口 401 但 Cookie 存在 | 模块未在 permit-all 放行清单内 | yaml 放行该模块前缀，重启 |
| iframe 白屏，Console 报 X-Frame-Options | nginx / IIS 配置了拒绝头 | 删除 `X-Frame-Options` / CSP 相关配置 |
| 跨机打开子系统数据为空 | Cookie 未写入目标机 | 首选经门户机 Nginx 反代实现同域访问（2.7）；未经反代直连时，子系统站点根目录部署 `camstar-cookie-bridge.html`；同机不同端口无此问题；Console 查看 `[camstar-diag]` 日志 |
| 经反代打开若依/芋道页面接口 404 或跳转异常 | `/prod-api`、`/admin-api` 的 proxy_pass 尾斜杠写法与后端部署不符 | 按后端是否带前缀（context-path）调整尾斜杠写法（2.7.3 尾斜杠说明）；access.log 的 upstream 字段确认请求实际落点 |
| Camstar 页面打开缓慢 | 页面本身或页内接口缓慢 | Console `[camstar-diag]` 自动区分 JUMP 侧 / Camstar 侧耗时 |
| `getUserName()` / `UserThreadLocal.get()` 返回空 | 白名单路径未写入上下文 | 业务代码判空处理；或将该接口移出白名单 |
| 页面可打开但数据为空 | 工号查询用户返回空 | 检查用户表 / 视图是否包含该工号 |
| 用户同步下拉中无某系统 | 该系统「新增」叶子未启用 | 接口管理页启用新增接口 |
| 注册推送报"接口返回错误" | 对方响应 code≠200 或字段不符 | 查看返回的 msg/message；核对 successField/successValue 配置 |
| camstar 型偶发失败后自动恢复 | 会话过期触发重登并重试一次 | 属正常机制；频繁出现时检查 SSO 登录接口稳定性 |
| 创建用户失败提示花名册占用 | 同 (系统, 工号) 已绑定其他主用户 | 先在花名册解绑 / 删除原记录，再创建用户 |
