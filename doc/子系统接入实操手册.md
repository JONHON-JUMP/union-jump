# 子系统接入改造手册（子系统侧视角）

> **本文只讲子系统自己怎么改**。JUMP 侧（菜单登记、Cookie 种植）由门户管理员配置，子系统团队不用管。
>
> 两条已验证可用的路线：
> - **若依子系统 → 照 4200**（`ruoyi4200-master`）
> - **芋道子系统 → 照 TFMS**（`TFMS-master/tfms`）
>
> 两者的核心是同一件事：**JUMP 打开子系统 = iframe 直开 + 请求自动带 Cookie `Nancal_Cam_SessionId`（值 = Base64(工号)）**。
>
> 子系统要做两件事：
>
> 1. 页面和接口**不强制走自己的登录**（放行）；
> 2. 从 Cookie 解出工号，作为"当前用户"。

## 接入前确认

| # | 检查项 | 说明 |
|---|---|---|
| 1 | **前端路由用 history 模式**（URL 不带 `#`） | JUMP 靠"链接是否带 #"区分通道：带 `#` 会走 OAuth 通道（需要另一套改造）；纯 http 直链才走 Cookie 直开。4200 前端 `vue4200/src/router/index.js:935`、TFMS `ui/src/router/index.js:458` 均为 `mode: 'history'` |
| 2 | **工号体系打通** | Cookie 解出的工号，子系统能查到用户（本库同名用户名/工号字段，或员工视图） |
| 3 | **部署同 hostname 不同端口** | Cookie 自动共享，零额外工作。跨机部署需在子系统前端站点根目录放一个 `camstar-cookie-bridge.html`（找门户团队拿） |
| 4 | **响应头不拒绝 iframe** | 框架默认已放行：4200 `SecurityConfig.java:135`、TFMS `MesWebSecurityConfigurerAdapter.java:117` 都有 `frameOptions().disable()`；若子系统前面有 nginx，确认没配 `X-Frame-Options DENY` / `CSP frame-ancestors` |

# 一、若依子系统（照 4200 改）

改动清单：**新建 2 个类 + 修改 3 个文件（注册、yml、日志切面）+ 业务 Controller 打 `@Anonymous` + 前端 3 处**

## 1.0 认证模型总览

**核心结论：ThreadLocal 只有一条填充路径——Cookie。JWT 只用来过 Security 那道门**

```
直接登录：/login 或 /ldapLogin（要密码，SysLoginService:90/:129）
   → 响应返回 token + cookiekey(Base64用户名)          ← SysLoginController:56/:67
   → 前端 setCookie(cookiekey) 种 Nancal_Cam_SessionId  ← user.js:42-44
   → 后续请求 = JWT 过 Security + Cookie 过拦截器

JUMP iframe（无 JWT）：
   → 前端白名单页面直进 + @Anonymous 接口放行
   → 后续请求 = Cookie 过拦截器（无 JWT）
```

| 场景 | 页面（前端路由守卫） | 业务接口（118 个 `@Anonymous`） | 管理接口（36 个未打注解） | ThreadLocal 内容 |
|---|---|---|---|---|
| JUMP iframe，无 JWT | 白名单页面 ✅ 直进 | ✅ Cookie 即可 | ❌ 无 JWT 被 Security 拒 | Cookie 工号查库 → `LCUser` |
| JUMP iframe，访问管理页 | ❌ 不在白名单 → 跳 4200 登录页 | — | — | — |
| 直接登录用户（有 JWT） | ✅ 任意 | ✅ | ✅ | **也是 Cookie 通道**（前端已补种 Cookie） |

三个容易误解的点：

1. **`/login`、`/ldapLogin` 不是"需要登录的页面"，是登录入口本身**（要密码）；
2. **没打 `@Anonymous` 的 36 个 Controller 全是系统管理/监控类**（SysUser/SysRole/SysMenu/
   SysDept、定时任务、操作日志、代码生成等）——JUMP 场景用不到，仍走 JWT；
3. **JWT 用户的 ThreadLocal 也不是从 JWT 填的**——4200 依赖"前端登录后补种 Cookie"的约定，
   拦截器对两类用户一视同仁走 Cookie 解码。另外白名单路径（login/getInfo/getRouters）
   放的是**假用户** `userCode="token"`（CamstarInfoInterceptor:48-50），不是真实信息。
   本手册 1.2 第 4 步的"无 Cookie 从 JWT 取用户"是改进版（4200 没有该分支）。

## 1.1 新建 `framework/interceptor/UserThreadLocal.java`

```java
package com.ruoyi.framework.interceptor;

import com.ruoyi.common.core.domain.entity.SysUser;

/**
 * 当前登录用户容器：拦截器写入，业务代码读取
 */
public class UserThreadLocal {
    private UserThreadLocal() {}

    private static final ThreadLocal<SysUser> LOCAL = new ThreadLocal<>();

    public static void put(SysUser user) { LOCAL.set(user); }
    public static SysUser get()          { return LOCAL.get(); }
    public static void remove()          { LOCAL.remove(); }
}
```

## 1.2 新建 `framework/interceptor/CamstarInfoInterceptor.java`

以 4200 的同名类为蓝本，修掉了它的几个坑（白名单配置化、Cookie 命中即 break、401 有响应体）：

```java
package com.ruoyi.framework.interceptor;

import com.alibaba.fastjson2.JSON;
import com.ruoyi.common.annotation.Anonymous;
import com.ruoyi.common.core.domain.AjaxResult;
import com.ruoyi.common.core.domain.entity.SysUser;
import com.ruoyi.common.utils.StringUtils;
import com.ruoyi.common.utils.SecurityUtils;
import com.ruoyi.common.utils.servlet.ServletUtils;
import com.ruoyi.framework.security.LoginUser;
import com.ruoyi.system.service.ISysUserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.net.InetAddress;
import java.util.Base64;
import java.util.List;

/**
 * 从 Cookie Nancal_Cam_SessionId(Base64工号) 识别当前登录用户（参照 ruoyi4200）
 */
@Component
public class CamstarInfoInterceptor implements HandlerInterceptor {

    public static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";
    /** 业务错误码：前端据此识别"门户身份失效" */
    public static final int UNAUTHORIZED_CAMSTAR = 4001;

    @Autowired
    private ISysUserService userService;

    /** 白名单 uri（contains 匹配）：本系统无需识别用户的接口 */
    @Value("#{'${camstar.whitelist:}'.split(',')}")
    private List<String> whitelist;

    /** 生产服务器 IP：非此 IP 视为开发环境 */
    @Value("${camstar.server-host-ip:}")
    private String serverHostIp;

    /** 开发环境测试工号 */
    @Value("${camstar.dev-user-code:}")
    private String devUserCode;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 1. @Anonymous（若依自带）标记的接口放行
        if (handler instanceof HandlerMethod) {
            HandlerMethod hm = (HandlerMethod) handler;
            if (hm.hasMethodAnnotation(Anonymous.class)
                    || hm.getBeanType().isAnnotationPresent(Anonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行
        String uri = request.getRequestURI();
        if (whitelist != null && whitelist.stream().anyMatch(u -> !u.isEmpty() && uri.contains(u))) {
            return true;
        }
        // 3. 开发环境兜底：非生产 IP 使用测试工号
        String userCode = resolveUserCode(request);
        if (StringUtils.isEmpty(userCode) && StringUtils.isNotEmpty(devUserCode) && !isProductionHost()) {
            userCode = devUserCode;
        }
        // 4. JWT 用户兜底：无 Cookie 但已通过 Security 认证（本系统直接登录的场景）→ 放行，
        //    并把 JWT 里的用户同样放进 ThreadLocal，业务代码取人只有一个入口
        if (StringUtils.isEmpty(userCode)) {
            try {
                LoginUser loginUser = SecurityUtils.getLoginUser();
                if (loginUser != null && loginUser.getUser() != null) {
                    UserThreadLocal.put(loginUser.getUser());
                    return true;
                }
            } catch (Exception ignore) {
                // 未认证，走最后的拒绝
            }
        }
        // 5. 工号查用户 → ThreadLocal；查不到拒绝
        if (StringUtils.isNotEmpty(userCode)) {
            SysUser user = userService.selectUserByUserName(userCode);
            if (user != null) {
                UserThreadLocal.put(user);
                return true;
            }
        }
        ServletUtils.renderString(response,
                JSON.toJSONString(AjaxResult.error(UNAUTHORIZED_CAMSTAR, "未获取到当前登录用户")));
        return false;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        UserThreadLocal.remove();   // 必须清理，防线程池串号
    }

    /** 遍历 Cookie 取工号，命中即返回 */
    private String resolveUserCode(HttpServletRequest request) {
        Cookie[] cookies = request.getCookies();
        if (cookies == null) {
            return null;
        }
        for (Cookie cookie : cookies) {
            if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                try {
                    return new String(Base64.getDecoder().decode(cookie.getValue()));
                } catch (IllegalArgumentException e) {
                    return null;
                }
            }
        }
        return null;
    }

    private boolean isProductionHost() {
        try {
            return StringUtils.isNotEmpty(serverHostIp)
                    && serverHostIp.equals(InetAddress.getLocalHost().getHostAddress());
        } catch (Exception e) {
            return false;
        }
    }
}
```

业务代码取当前用户：

```java
SysUser currentUser = UserThreadLocal.get();
String userCode = currentUser.getUserName();   // 即工号
```

> **JWT 用户（不走门户、本系统直接登录的）两种已验证处理方式**：
> - **4200 实际做法**：登录响应返回 `cookiekey`=Base64(用户名)（`SysLoginController:56/:67`），
>   前端登录后自己写 `Nancal_Cam_SessionId` Cookie——JWT 用户最终也带 Cookie，拦截器统一走 Cookie 通道；
> - **TFMS 实际做法**：拦截器无 Cookie 时检查 `Authorization: Bearer` 头，有则放行并放哨兵值
>   `"token"`（`CamstarInfoInterceptor:85-93`），业务按 `"token".equals(userCode)` 分流到芋道标准取用户
>   （`UserServiceImpl:31-33`）；
> - 上面代码是本手册的合体改法（4200/TFMS 均非如此）：无 Cookie 时直接从 SecurityContext 取
>   `SecurityUtils.getLoginUser()` 塞进 ThreadLocal——JWT/Cookie 两类用户对业务代码完全透明。
>   前提依赖一个事实：Spring Security 过滤器在拦截器**之前**执行，拦截器能拿到已认证的上下文。

> 注解差异：4200 原版拦截器判断的是它自建的 `@CamStarAnonymous`
> （`com.jonhon.framework.aspectj.lang.annotation.CamStarAnonymous`，CamstarInfoInterceptor.java:6）。
> 上面代码用的是标准若依 4.7+ 自带的 `com.ruoyi.common.annotation.Anonymous`；
> 老版本若依没有该注解时，从 4200 抄 `@CamStarAnonymous` + `PermitAllUrlProperties`（Security 层同步放行）。

## 1.3 修改 `framework/config/ResourcesConfig.java`（注册）

```java
@Autowired
private CamstarInfoInterceptor camstarInfoInterceptor;   // 新增注入

@Override
public void addInterceptors(InterceptorRegistry registry) {
    // 顺序与 4200 原版一致（ResourcesConfig.java:52-53）：
    // preHandle 按注册顺序执行，camstar 在前 → 无凭证请求先被它拒（返回 4001）
    registry.addInterceptor(camstarInfoInterceptor).addPathPatterns("/**");   // ← 新增
    registry.addInterceptor(repeatSubmitInterceptor).addPathPatterns("/**");
}
```

> 时机说明：拦截器 `preHandle` 在 Controller 之前、**Spring Security 过滤器之后**执行；
> `afterCompletion` 在响应完成后执行（无论成功异常）。多个拦截器 preHandle 按注册顺序、
> afterCompletion 逆序；某拦截器 preHandle 返回 false 后，前面已返回 true 的拦截器的
> afterCompletion 仍会执行，所以 ThreadLocal 清理是安全的。

## 1.4 Security 放行：核对配置 + 给业务 Controller 打 `@Anonymous`

4200 实际有两层放行，**第二层才是关键**：

**第一层：SecurityConfig 基础三段**（标准若依默认已有，`SecurityConfig.java:126/:128/:135`）：

```java
.antMatchers("/login", "/register", "/ldapLogin","/captchaImage").permitAll()
.antMatchers(HttpMethod.GET, "/", "/*.html", "/**/*.html", "/**/*.css", "/**/*.js", "/profile/**").permitAll()
.headers().frameOptions().disable()
```

**第二层：要挂 JUMP 的 Controller 类上打 `@Anonymous`**（4200 覆盖 118/154 个 Controller）：

```java
@CrossOrigin
@RestController
@Anonymous                    // ← 被 PermitAllUrlProperties 扫描后 Security 层 permitAll
@RequestMapping("/system/areaInfo")   //（4200 实例：D2FunctionalareaEntityController）
public class D2FunctionalareaEntityController extends BaseController {
```

链路：`@Anonymous` → `PermitAllUrlProperties.java:47` 扫描 → `SecurityConfig.java:112`
`permitAllUrl.getUrls().forEach(...permitAll())` → 无 token 可调。
同时拦截器对 `@Anonymous` 也直接放行（1.2 代码第 1 步）——**接口身份完全靠 Cookie**。

> 未打 `@Anonymous` 的 36 个 Controller 是系统管理/监控类（SysUser/SysRole/SysMenu/SysDept、
> 定时任务、代码生成等），仍需 JWT——JUMP 场景用不到，属正常保留。
> 与 TFMS 对比：TFMS 用 yaml `permit-all_urls` 按路径前缀放行（2.3），4200 用注解逐个 Controller 放行，
> 思想相同。新系统按口味选一种即可。

# 二、芋道子系统（照 TFMS 改）

TFMS 的模式：**Security 放行目标模块（免 token）+ 拦截器从 Cookie 解工号 + Controller 无 token 时兜底**。
改动清单：**新建 1 个类 + 修改 2 个文件 + 前端 3 处**。

## 2.0 认证模型总览（TFMS 实际行为，先看这个）

**核心结论：JWT 用户与 Cookie 用户走的是两条不同的通道——
JWT 用户的信息在 SecurityContext（由 Token 过滤器从 Redis 校验 token 后填入）；
Cookie 用户的信息在拦截器的 ThreadLocal（仅工号字符串，用时查库补全）。**

### 2.0.1 请求要过的关卡（按执行顺序）

| 顺序 | 关卡 | 代码位置 | 干什么 |
|---|---|---|---|
| 1 | **CORS 配置** | `MesWebSecurityConfigurerAdapter:105-112` | originPattern `*` + allowCredentials，跨端口带 Cookie 的前提 |
| 2 | **TokenAuthenticationFilter**（Security 过滤器） | 同文件 `:153` 注册；过滤器本体在 security starter | 有 `Authorization: Bearer` → 查 Redis（`checkAccessToken:73`）→ 构建 `LoginUser` 塞进 **SecurityContext**（`setLoginUser:58`）；没有头则什么都不做 |
| 3 | **Security 授权规则** | 同文件 `:126-149` | 依次匹配：静态资源(:130) → `@PermitAll` 注解(:132-135) → yaml `permit-all_urls`(:137) → App API(:139) → **硬编码 `/admin-api/tool/**`(:140) 和 `/api/**`(:141)** → 验证码(:143) → 兜底 `anyRequest().authenticated()`(:149)。匹配到放行；都不匹配且无认证 → 401 |
| 4 | **CamstarInfoInterceptor**（MVC 拦截器，Security 之后） | `MesWebAutoConfiguration:150` 注册 | OPTIONS 放行(:37) → `@CrossFilter` 放行(:42) → URL 白名单放行并放哨兵 `"token"`(:49-59) → **Cookie 解码工号 → ThreadLocal**(:60-75) → Bearer 回退放 `"token"`(:85-93) → 全无则拒绝(:95) → `afterCompletion` 清理(:103) |
| 5 | **Controller 取人** | `AuthController:131-141` 等 | `getLoginUserId()`（SecurityContext）有值 → token 用户；为 null → `CamstarInfoInterceptor.getUserName()`（ThreadLocal 工号）查库 |

### 2.0.2 流程 A：本系统用户直接登录（有 JWT）

```
登录页输入工号+密码（验证码由 mes.captcha.enable 控制，TFMS 已关）
→ POST /admin-api/system/auth/login
   关2：无 Bearer 头，SecurityContext 保持空
   关3：/login 标了 @PermitAll（AuthController:74）→ 放行
   关4：URL 含 "login" 命中白名单 → ThreadLocal 放哨兵 "token"
→ AdminAuthServiceImpl.login(:136)：密码校验 → createTokenAfterLoginSuccess(:157)
→ oauth2TokenService.createAccessToken：token 写入 Redis
→ 响应 accessToken/refreshToken（无 cookiekey，与 4200 不同）
→ 前端 setToken → sessionStorage（ui/src/utils/auth.js:19-22）

后续每个业务请求带 Authorization: Bearer xxx：
   关2：checkAccessToken(Redis) → LoginUser → SecurityContext ✅
   关3：任意 URL（已认证）→ 过
   关4：无 Cookie → 命中 Bearer 回退 → ThreadLocal 放哨兵 "token"
   关5：getLoginUserId() 有值 → 正常芋道取用户
```

**TFMS 的 JWT 用户不种 Camstar Cookie**（全局搜不到 cookiekey）——它靠拦截器的
Bearer 回退分支通过关 4，与 4200"前端种 Cookie"是两种不同策略。

### 2.0.3 流程 B：JUMP 用户访问（无 JWT，只有 Cookie）

```
JUMP 登录（工号）→ 前端写 Nancal_Cam_SessionId = Base64(工号)
→ iframe 打开 TFMS 白名单页面（/tool 前缀、大屏页，permission.js:12-16）
→ 页面发接口请求（withCredentials: true，request.js:31，Cookie 自动带上）

请求 /admin-api/tool/xxx：
   关2：无 Bearer 头 → SecurityContext 保持空
   关3：/admin-api/tool/** 双保险放行（SecurityConfig:140 硬编码 + yaml permit-all_urls）→ 过
   关4：Cookie Nancal_Cam_SessionId → Base64 解码 → 工号 → ThreadLocal ✅
   关5：getLoginUserId() = null → getUserName() 拿工号
       → getUserInfo(userCode) 查 Oracle 视图 V_NCJ_USERINFO_DEPT（SysUserViewMapper.xml:14）
       → 得到姓名/角色 → 返回权限数据

请求非放行模块（如 /admin-api/system/**）且无 token：
   关3：兜底 anyRequest().authenticated() → 401（AuthenticationEntryPointImpl）
```

### 2.0.4 用户信息存放位置

| 位置 | 内容 | 谁写入 | 生命周期 |
|---|---|---|---|
| **SecurityContext**（LoginUser：userId/userType） | token 用户身份 | TokenAuthenticationFilter（每请求） | 请求结束由框架清 |
| **CamstarInfoInterceptor 的 ThreadLocal**（Map：工号或哨兵 `"token"`） | Cookie 用户工号 | CamstarInfoInterceptor（每请求） | `afterCompletion` 手动清（:104） |
| **Redis**（oauth2_access_token） | token 本体（userId/过期时间） | 登录时 createAccessToken | 过期/登出删除 |
| **前端 sessionStorage**（ACCESS_TOKEN/REFRESH_TOKEN） | token 字符串 | 登录成功 setToken | 关标签页即失效 |
| **Oracle 视图 V_NCJ_USERINFO_DEPT** | 工号→姓名/角色 | DBA 维护 | — |

### 2.0.5 放行/校验速查矩阵

| 请求 | 关2（Token 过滤器） | 关3（Security 授权） | 关4（拦截器） | 关5 取人 |
|---|---|---|---|---|
| `/admin-api/tool/**` + Cookie | 跳过（无头） | ✅ 双保险放行 | ✅ 工号→ThreadLocal | `getUserName()` 查视图 |
| `/admin-api/tool/**` + Bearer | ✅ LoginUser | ✅ 放行 | ✅ 哨兵 "token" | `getLoginUserId()` |
| 其他 `/admin-api/**` + Bearer | ✅ LoginUser | ✅ 已认证 | ✅ 哨兵 "token" | `getLoginUserId()` |
| 其他 + 只有 Cookie | 跳过 | ❌ 401（模块没放行） | 到不了 | 到不了 |
| `/login` `/ldapLogin` | 跳过 | ✅ @PermitAll | ✅ 白名单+哨兵 | — |
| OPTIONS 预检 | — | — | ✅ 直接放行 | — |

## 2.1 新建拦截器（放在 web starter 或本工程任意 config 包）

以 TFMS 的 `CamstarInfoInterceptor`（`tool-framework/spring-boot-starter-web/.../CamstarInfoInterceptor.java`）为蓝本，修掉了它的两个坑（`getUserName()` NPE、拒绝时无响应体）：

```java
package cn.xxx.module.infra.framework.web.config;   // 换成本工程实际包

import cn.xxx.framework.common.pojo.CommonResult;
import cn.xxx.framework.common.util.servlet.ServletUtils;

import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.lang.reflect.Method;
import java.util.HashMap;
import java.util.Map;

import static cn.xxx.framework.common.exception.enums.GlobalErrorCodeConstants.UNAUTHORIZED;

/**
 * 从 Cookie Nancal_Cam_SessionId(Base64工号) 识别当前登录用户（参照 TFMS）
 */
public class CamstarInfoInterceptor implements HandlerInterceptor {

    private static final ThreadLocal<Map<String, Object>> CONTEXT = new ThreadLocal<>();
    private static final String CAMSTAR_COOKIE = "Nancal_Cam_SessionId";

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        // 0. CORS 预检放行
        if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
            return true;
        }
        // 1. 免鉴权注解放行：本工程自定义的 @CamstarAnonymous（见 2.2）
        if (handler instanceof HandlerMethod) {
            Method method = ((HandlerMethod) handler).getMethod();
            Class<?> clazz = method.getDeclaringClass();
            if (clazz.isAnnotationPresent(CamstarAnonymous.class)
                    || method.isAnnotationPresent(CamstarAnonymous.class)) {
                return true;
            }
        }
        // 2. 白名单放行（芋道接口风格，参照 TFMS）
        String url = request.getRequestURL().toString();
        if (url.contains("login") || url.contains("ldapLogin")
                || url.contains("get-permission-info") || url.contains("list-all-simple")
                || url.contains("get-unread-count") || url.contains("/api")) {
            return passWith("token");
        }
        // 3. Cookie 解工号（命中即 break）
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if (CAMSTAR_COOKIE.equals(cookie.getName())) {
                    try {
                        String userCode = new String(
                                java.util.Base64.getDecoder().decode(cookie.getValue()), "utf-8");
                        return passWith(userCode);
                    } catch (IllegalArgumentException e) {
                        break;   // 非法 Base64，走后面的 token 回退
                    }
                }
            }
        }
        // 4. 回退：带 Bearer token 的正常芋道请求也放行（兼容非门户场景）
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return passWith("token");
        }
        // 5. 无凭证：返回 401 JSON（TFMS 原版这里裸 return false，前端拿不到任何信息，已修）
        ServletUtils.writeJSON(response, CommonResult.error(UNAUTHORIZED));
        return false;
    }

    private boolean passWith(String userCode) {
        Map<String, Object> map = new HashMap<>();
        map.put("CamstarUserCode", userCode);
        CONTEXT.set(map);
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest req, HttpServletResponse resp,
                                Object handler, Exception ex) {
        CONTEXT.remove();
    }

    /** 业务代码统一从这里取工号；OPTIONS 预检和 @CamstarAnonymous 路径没放过上下文，
     *  此处返回 null（TFMS 原版直接 contextHolder.get().get(...) 会 NPE，已修；
     *  白名单/token 回退路径 TFMS 是放了 "token" 上下文的） */
    public static String getUserName() {
        Map<String, Object> map = CONTEXT.get();
        return map == null ? null : String.valueOf(map.get("CamstarUserCode"));
    }
}
```

配套注解（新建，TFMS 用的是它工程里的 `@CrossFilter`，新工程自己建一个更干净）：

@Retention(RetentionPolicy.RUNTIME)

}
```

业务代码取工号：

```

# 四、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| iframe 里跳到了子系统自己的登录页 | 页面不在前端白名单 | permission.js 白名单/前缀补上该页面 |
