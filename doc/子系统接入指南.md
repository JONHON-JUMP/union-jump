# 子系统接入 JUMP 门户指南（以 4200 / ruoyi4200 为参照）

> 目标读者：需要把新的子系统（独立前后端、独立部署）挂到 JUMP 门户里，并实现"JUMP 登录后免登录访问"的开发人员。
>
> 现状：4200（ruoyi4200-master）已按本文所述方式接入并可用。

---

## 一、整体原理

JUMP 把子系统当作**外链 iframe** 打开，身份靠一个共享 Cookie 传递：

```
JUMP 登录（工号）
  → ① JUMP 前端写 Cookie：Nancal_Cam_SessionId = Base64(工号)，path=/
  → ② iframe 打开子系统页面（同 hostname 不同端口 → 浏览器 Cookie 自动共享）
  → ③ 子系统 Security 放行静态资源 + 登录接口 → 页面能在 iframe 里加载
  → ④ 子系统拦截器解码 Cookie → 查用户 → 放入 ThreadLocal → 业务接口认人
```

**身份的唯一载体就是 Cookie `Nancal_Cam_SessionId`**，其余所有改动都是围绕两件事：
1. 让这个 Cookie 在子系统域下存在（JUMP 前端负责种）；
2. 让子系统后端能识别它（子系统拦截器负责解）。

## 二、部署前提

| 场景 | 做法 | 依据 |
|---|---|---|
| 子系统与 JUMP **同机不同端口**（4200 现状） | 无需额外部署，Cookie 天然共享 | `jonhonjump-ui/.../utils/camstarCookie.js:3` 注释 |
| 子系统在**其他机器/域** | 把 `jonhonjump-ui/jonhonjump-ui-admin-vue2/public/camstar-cookie-bridge.html` 拷到子系统站点**根目录**。JUMP 打开子系统时会用隐藏 iframe 调它种 Cookie（尽力而为、不阻塞打开，失败静默忽略） | `camstarCookie.js` 的 `seedCamstarCookieForUrlInBackground()` |

另外两个硬前提：

1. **JUMP 登录用户名 = 子系统能识别的工号**（同一套工号体系）；
2. 子系统要有 **"工号 → 用户"** 的查询能力（表或接口均可）。

## 三、JUMP 侧：只做配置，不改代码

1. 管理后台 → 外部系统菜单（`sub_system_menu` 表，接口 `/system/sub-system-menu`，见 `jonhonjump-module-system/.../SubSystemMenuController.java`）登记菜单：
   - `path` 填子系统完整 URL（如 `http://192.168.240.127:xxxx/...`）；
   - 菜单为外链 iframe 类型。
2. 前端自动完成以下逻辑（无需开发）：
   - 链接是纯 http（不含 `#`）→ 识别为 `kind: 'camstar'` → InnerLink iframe 渲染（`store/modules/portal.js:1144`）；
   - 打开前自动 `ensureLocalCamstarCookie()` 写本机 Cookie（`layout/components/InnerLink/index.vue:256`）；
   - 跨机时自动 `seedCamstarCookieForUrlInBackground()` 调目标机的 bridge 页种 Cookie（`InnerLink/index.vue:257`）；
   - 换号重新登录后自动纠偏旧 Cookie（`camstarCookie.js` 的 `resolveCamstarCookieKey()`：当前登录用户名永远最权威）；
   - 退出登录自动清 Cookie（`clearCamstarCookie()`）。

### 4.1 `UserThreadLocal`（照抄）

参照：`framework/interceptor/UserThreadLocal.java`

```java
public class UserThreadLocal {
    private UserThreadLocal() {}
    private static final ThreadLocal<XxxUser> LOCAL = new ThreadLocal<>();
    public static void put(XxxUser u) { LOCAL.set(u); }
    public static XxxUser get()        { return LOCAL.get(); }
    public static void remove()        { LOCAL.remove(); }
}
```

业务 Controller/Service 里统一用 `UserThreadLocal.get()` 取当前用户，不层层传参。

### 4.2 `@XxxAnonymous` 注解（照抄）

参照：`framework/aspectj/lang/annotation/CamStarAnonymous.java`

标在 Controller 类或方法上 = 该接口跳过拦截器鉴权（用于健康检查、公共接口等）。

### 4.3 核心拦截器（照抄改名）

参照：`framework/interceptor/CamstarInfoInterceptor.java`

固定逻辑五步：

```
① 白名单放行（本系统的启动/登录类接口）
② 读 Cookie Nancal_Cam_SessionId → Base64 解码得到工号
③ 工号查用户（queryCurrentUser）
④ 命中 → UserThreadLocal.put(user)
⑤ 查不到 → 返回 UNAUTHORIZED 错误 JSON，拦截请求
```

骨架：

```java
@Component
public class XxxInfoInterceptor implements HandlerInterceptor {
    @Autowired
    private XxxUserService userService;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        // 1) @XxxAnonymous 注解放行
        if (handler instanceof HandlerMethod) {
            Method method = ((HandlerMethod) handler).getMethod();
            Class<?> clazz = method.getDeclaringClass();
            if (clazz.isAnnotationPresent(XxxAnonymous.class)
                    || method.isAnnotationPresent(XxxAnonymous.class)) {
                return true;
            }
        }
        // 2) 白名单 URL 放行（本系统的登录/初始化接口）
        // 3) 遍历 Cookie 找 Nancal_Cam_SessionId，Base64 解码 → 查用户 → ThreadLocal
        // 4) 查不到用户：renderString(UNAUTHORIZED JSON) 并 return false
        // 5) 开发环境兜底：非生产 IP 使用测试工号（建议改为配置项，见第六节）
        ...
        return true;
    }

    @Override
    public void afterCompletion(...) {
        UserThreadLocal.remove();   // 必须有！防线程池复用导致用户串号
    }
}
```

### 4.5 Security 配置调整（照抄）

参照：`framework/config/SecurityConfig.java`。子系统若也是 RuoYi / Spring Security，三个关键点：

```java
// ① 静态资源放行：页面（html/js/css）能在 iframe 里加载
.antMatchers(HttpMethod.GET, "/", "/*.html", "/**/*.html", "/**/*.css", "/**/*.js", "/profile/**").permitAll()

// ② 自动登录/换 token 接口放行
.antMatchers("/login", "/ldapLogin", "/captchaImage").permitAll()

// ③ 允许被 JUMP iframe 嵌入 —— 最容易漏的一步！
.headers().frameOptions().disable()
```

CORS：`addAllowedOriginPattern("*")` + `setAllowCredentials(true)`。

> 注意：拦截器是 Spring MVC 层，运行在 Spring Security **之后**。若子系统保留自己的 JWT 体系（`anyRequest().authenticated()`），
> 业务接口仍然需要 token —— 所以子系统前端要做一步"Cookie 工号静默登录"（见 4.7）。

### 4.7 子系统前端（4200 前端不在本仓库，单独说明）

4200 拦截器白名单里的 `login / ldapLogin / getInfo / getRouters` 表明其前端流程是：
**读 Cookie → 解码工号 → 静默调登录接口换自己的 JWT → 再走业务请求**。

新子系统二选一：

1. 保持自己的 token 体系：加一个"Cookie 工号静默登录"入口（推荐沿用，改动小）；
2. 像 4200 的业务接口那样：前端不传 token，接口身份完全靠 Cookie + 拦截器。

## 五、排查手段

JUMP 前端内置了 Camstar 打开链路诊断（`utils/camstarOpenDiag.js`）：
打开子系统时按 `JUMP_CAMSTAR_TRACE` 递增 traceId，逐步打点 `cookie`、`iframe-mount`、`iframe-load`。
排查"子系统打不开/接口 401"时，先看浏览器控制台这些打点，再确认：

1. 子系统域下是否真的有 `Nancal_Cam_SessionId`（DevTools → Application → Cookies）；
2. Cookie 值 Base64 解码后是否是当前登录工号；
3. 子系统后端接口返回是否为 `未获取到当前登录用户`（拦截器放行了页面但用户没查到）；
4. 跨机部署时 bridge 页是否返回 `camstar-cookie-seeded` postMessage。

## 六、新子系统不要照抄的坑（建议改进）

| # | 4200 现状 | 问题 | 建议 |
|---|---|---|---|
| 1 | 白名单用 `URL.contains("login")` 等模糊匹配（CamstarInfoInterceptor.java:46） | URL 任意位置含 "login" 即放行，过宽 | 精确路径匹配；白名单抽成配置 |
| 2 | Cookie 遍历命中后不 `break`（:74） | 继续空转 | 命中即 break |
| 3 | 生产 IP 硬编码 `192.168.240.127` + 测试工号 `16358`（:32, :82） | 换环境要改代码 | 抽成 `application.yaml` 配置项 |
| 4 | `Base64(工号)` 即凭证 | 无签名，知道工号即可伪造，属弱安全点 | 内网可接受；要求更高的子系统可让 JUMP 后端签发带签名的 ticket、子系统验签（升级方向） |

## 七、验收清单

- [ ] iframe 能打开子系统页面（静态资源放行 OK）；
- [ ] 打开后接口不报"未获取到当前登录用户"（拦截器 OK）；
- [ ] JUMP 换号重新登录后再打开子系统，身份跟着变；
- [ ] JUMP 退出登录后，子系统 Cookie 被清除；
- [ ] 两个账号同时操作互不串号（`afterCompletion` 清理 OK）；
- [ ] 跨机部署时 bridge 页种 Cookie 生效（postMessage 回执 `camstar-cookie-seeded`）。
