# Chrome 82 兼容适配方案

## 根因

`package.json` 的 `browserslist: ["> 1%", "last 2 versions"]` 以当前（2026）数据解析后**不包含 Chrome 82**，导致 Babel/core-js 不为 82 转译和注入 polyfill、autoprefixer 也不为 82 加前缀。叠加代码里直接用了几个 Chrome 82 尚不支持的 JS/CSS 特性，82 上会出现功能报错（卡死/转圈）和布局挤压（显得"卡"）。

## 排查结果清单

| 问题 | 位置 | Chrome 要求 | 82 上的表现 |
|---|---|---|---|
| browserslist 不含 82 | `package.json` | — | polyfill/前缀缺失（根因） |
| `String.replaceAll` | `src/views/infra/codegen/index.vue:282` | 85+ | 代码生成页报 TypeError |
| CSS `inset` | `src/assets/styles/login-mian.css:32,88` | 87+ | 登录遮罩定位失效 |
| CSS flex `gap`（grid gap 无需改，66+ 已支持） | 见下 | 84+ | 元素挤成一团 |
| `mask-size` 缺 `-webkit-` 前缀 | `src/components/SvgIcon/index.vue:58` | 120+ | 外链图标显示异常 |

flex gap 具体位置（其余 gap 均为 grid，已确认无需改）：
- `src/assets/styles/login-mian.css:126,303,391`（登录页）
- `src/layout/components/PortalShell.vue:840`（门户头部）
- `src/views/mes/process/card/index.vue:420,431,435,439,440,478`（MES 工序卡）
- `src/views/system/subSystem/apiConfig/index.vue:1100,1171,1176,1186`
- `src/views/system/subSystem/user/index.vue:984`

依赖包（node_modules）语法已扫描：`?.`/`??`/static class fields 均为 Chrome 80/72 已支持，无需 transpileDependencies。

## 修改内容

1. **`package.json`** — browserslist 改为 `["> 1%", "last 2 versions", "chrome >= 82"]`，让 core-js 按需 polyfill、autoprefixer 按 82 加前缀（一次性兜住所有 API/前缀缺失）
2. **`codegen/index.vue`** — `replaceAll('.', '/')` 改为 `.split('.').join('/')`（不依赖 polyfill，双保险）
3. **`login-mian.css`** — `inset: 0` / `inset: -2px` 改为 `top/right/bottom/left` 等价写法；3 处 flex `gap` 改为子元素 margin（`:not(:last-child)` 方式）
4. **上述 3 个业务页面 + PortalShell** — flex `gap` 统一改为等价 margin 写法（行方向 `margin-right`，列方向 `margin-bottom`，wrap 场景行尾 margin 略宽，属可接受的通用兼容做法）
5. **`SvgIcon/index.vue`** — 补 `-webkit-mask-size: cover`

## 验证

1. `npm run build:prod` 构建
2. 检查 dist 产物：CSS 中不再有裸 `inset:`；JS 中无未转译的 `replaceAll` 裸调用；autoprefixer 前缀已生成
3. 交付后在 Chrome 82 真机验证：登录页、门户首页、MES 工序卡、子系统 API 配置/登记用户、代码生成页
