# 修复版本号 TTL bug（导致闲置后误提示重登）

## 问题
`portal_rbac_version:{subId}` 和 `user_permission_rbac_version:{userId}` 用 `increment` 无 TTL（永久），但权限包 `portal:perm:context`（3小时）和 `portal_my_menus`（30分钟）有 TTL。闲置后权限包过期删除，版本号还在 → 子系统 `isPortalPermContextAlive` 检测到 `existsInRedis=false` → 误判权限变更 → 弹"请重新登录"。

## 修复方案（2 个 DAO 文件）
给版本号 `bump` 的 `increment` 后加 `expire`，TTL 与权限包对齐（3 小时）。这样版本号和权限包同步过期，不会出现"权限包没了但版本号还在"的不一致。

- `PortalRbacVersionRedisDAO.bump`：`increment` 后 `expire(formatKey, Duration.ofHours(3))`
- `PermissionRbacVersionRedisDAO.bump` / `bumpList`：同上 `expire`

## 配套：权限包重建时刷新版本号 TTL（1 个 Service 文件）
`SubSystemPermissionContextServiceImpl.rebuildAndCache` 重建权限包时，同步刷新该子系统版本号 TTL，保证版本号不会比权限包先过期。

## 不改的
- 探测逻辑（`isPortalPermContextAlive`）不动
- 权限包 TTL（3小时）不动
- 角色变化 evict 链路不动（已有，完整）

## 验证
1. mvn compile 通过
2. 闲置 3 小时后，版本号和权限包同时过期 → 子系统探测不再误判变更（权限包 miss 时版本号也 miss，子系统重新 SSO 拉取，不弹重登）
