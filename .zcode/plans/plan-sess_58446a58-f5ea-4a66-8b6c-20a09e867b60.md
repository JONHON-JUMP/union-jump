# Camstar 角色接口接入 JUMP 接口管理（查询/新增/删除）

## 范围（明确不做）

- ❌ 角色修改（camstar 无纯改名接口，本次不补）
- ❌ 角色↔页面、角色↔用户绑定（建出来的是"裸角色"，无任何页面权限）
- ❌ 角色管理操作页面（用接口管理"在线测试"完成增删查）
- ❌ camstar_api（C# 侧）零改动

## 一、Camstar 对接契约（已实测代码确认）

| 叶子 | 地址（拼 baseUrl） | 方法 | 请求体 | 响应 |
|---|---|---|---|---|
| 角色查询 | `/BasicData/Role/getRoleInfo` | POST | `{"workshopCode":"4200"}` | `{code:200, rows:[{roleId,roleName,workshopCode}], data:条数}` |
| 角色新增 | `/BasicData/Role/updateRoleInfo` | POST | `[{"roleName":"xxx","workshopCode":"4200"}]`（roleId 不传→走 addRole） | `{code:200}` |
| 角色删除 | `/BasicData/Role/deleteRoleInfo` | POST | `{"roleId":"..."}` | `{code:200}` |

关键约定：
- 全部 **POST**（C# `Json()` 未放开 GET）；JSON body；成功判定 `code==200`，失败信息在 `message`
- 新增/删除要求会话 Cookie 里的工号挂有 **「管理员」或「Administrator」角色**（`checkIsAdmin`）→ 接口管理"会话鉴权"里配的**调用工号必须是 Camstar 管理员**；查询无此要求。三个叶子默认 `withSession=true`
- 新增接口 `updateRoleInfo` 传**裸 JSON 数组**（与现网人员 `addOrUpdateUser` 同款绑定方式）；`pageCodeStr` 不传 → 建出的角色不带任何页面，正是需求要的"裸角色"

## 二、后端改动（jonhonjump-module-system，5 文件 + 1 SQL）

purpose 取值：`role_query` / `role_create` / `role_delete`

1. **`SubSystemApiConfigDO.java`**：加 3 列字段 `apiRoleQuery` / `apiRoleCreate` / `apiRoleDelete`（varchar，存叶子 JSON，照抄 apiQuery 注释风格）
2. **`SubSystemApiConfigSaveReqVO.java`** / **`SubSystemApiConfigRespVO.java`**：同步加 3 字段
3. **`SubSystemApiConfigServiceImpl.java`**：
   - `validateJsonFields` 的 jsonFields 数组加 3 个新字段
   - `resolveEndpointJson` switch 加 3 个 case（`role_query`/`role_create`/`role_delete` → 对应新列）→ **在线测试 `/test` 链路即刻可用，无需新控制器**
4. **新 SQL `sql/postgresql/upgrade_20260903_role_api.sql`**（幂等，照 upgrade_20260829 风格）：
   - `ALTER TABLE sub_system_api_config ADD COLUMN IF NOT EXISTS api_role_query/api_role_create/api_role_delete varchar(512)`
   - 预填：`api_type='camstar'` 且 `api_role_query` 为空的行，写入 3 个默认叶子 JSON（enabled=true, POST, 上表地址）

## 三、前端改动（仅 `src/views/system/subSystem/apiConfig/index.vue`）

1. **purpose 下拉**（模板 150-156 行）：加 3 项 `role_query`角色查询 / `role_create`角色新增 / `role_delete`角色删除
2. **`PURPOSES` 数组**（246 行）加 3 值（在线测试校验用）
3. **`isPersonPurpose`**（531 行）：把 3 个 role_* 加进列表（让"携带会话 Cookie"开关对角色叶子也显示，改名 `isWithSessionPurpose`）
4. **`CAMSTAR_SAMPLES`**（248 行）加 3 个默认测试样例（用上表的请求体）
5. **`buildDefaultCatalog`**（355 行）：与 `dir-person` 同级加 `dir-role`（名称"角色"）+ 3 个叶子（默认地址/方法/用途如上表）

## 四、验证

1. `mvn compile -pl jonhonjump-module-system -am`
2. 执行 upgrade SQL
3. 页面：接口管理 → Camstar人员管理 → 出现"角色"目录（3 叶子，默认地址已填）→ 逐叶子在线测试：
   - 查询：样例 `{"workshopCode":"4200"}` → 返回 rows 角色列表
   - 新增：样例 `[{"roleName":"JUMP测试角色","workshopCode":"4200"}]` → code:200，再用查询叶子确认出现
   - 删除：`{"roleId":"<上一步查到的id>"}` → code:200，查询确认消失
4. 失败场景抽查：调用工号非管理员时，新增/删除返回 `xxx不具备权限`（查询不受影响）

## 五、注意点

- 调用工号必须是 Camstar 管理员（在 Camstar 侧给该工号挂「管理员」或「Administrator」角色），否则新增/删除 500
- 建出的角色是裸角色（ROLEDEF 一行，NOTES=车间编码），在 Camstar Portal 里不出现（无页面权限）——符合需求预期
- http 型系统配置角色叶子也能在线测试（测试链路与 apiType 无关），但默认目录只对 camstar 型自动补
