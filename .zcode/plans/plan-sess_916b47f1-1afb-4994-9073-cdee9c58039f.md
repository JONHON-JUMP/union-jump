# sub_system_api_config 竖向化重构(一行一接口)

## 目标
把"一行一系统、接口塞 JSON 列"改为:**主表(系统级配置)+ 接口子表(一行一个接口)**。非 camstar(http 型)系统沿用同一结构:接口行与适配器类型无关,`api_type` 仍在主表决定适配器,`param_mapping/response_mapping` 留在主表(系统级,现状语义)。今后新增接口类型 = 加一行接口记录,不改表结构。

已确认的决策:拆行后**删除旧列**;前端树**固定分组**(废弃 api_catalog 自定义目录)。

## 一、SQL 迁移脚本(新增 `sql/postgresql/upgrade_20260930_api_endpoint.sql`,幂等)

1. **建表** `sub_system_api_endpoint`:
   - `id(bigint PK, seq=sub_system_api_endpoint_seq)`、`sub_system_id`、`purpose(varchar32, query/create/update/delete/team_combo/role_query/role_create/role_delete,空串=未指定用途)`、`group_code(varchar32, person/role/other)`、`name`、`url(varchar512)`、`method(默认POST)`、`enabled(默认1)`、`with_session(默认1)`、`sort` + BaseDO 审计列
   - 唯一索引 `(sub_system_id, purpose) WHERE deleted=0 AND purpose<>''`(与前端"同用途唯一"约束一致)
2. **拆行迁移**:8 个 JSON 列各拆为一行,`api_query/api_create/api_update/api_delete/api_team_combo → group person`,`api_role_query/api_role_create/api_role_delete → group role`;字段映射 `COALESCE(j->>'url', j->>'path')`、method 缺省 POST、enabled/withSession 缺省 1;`NULLIF(col,'')::jsonb` + `NOT EXISTS` 幂等
3. **删旧列**:`ALTER TABLE sub_system_api_config DROP COLUMN IF EXISTS api_query,api_create,api_update,api_delete,api_team_combo,api_role_query,api_role_create,api_role_delete,api_catalog`
4. 主表保留:base_url/api_type/auth_type/auth_config/param_mapping/response_mapping/delete_tip/超时/status(鉴权仍系统级)

## 二、后端(jonhonjump-module-system)

**新增 3 个文件**:
- `dal/dataobject/user/SubSystemApiEndpointDO.java`(@TableName/@KeySequence/@TenantIgnore,同主表风格)

- `controller/admin/user/vo/subsystem/SubSystemApiEndpointVO.java`(purpose/groupCode/name/url/method/enabled/withSession/sort)

**修改**:
- `SubSystemApiConfigDO` / `SubSystemApiConfigSaveReqVO` / `SubSystemApiConfigRespVO`:删 9 个 apiXxx + apiCatalog 字段,VO 加 `List<SubSystemApiEndpointVO> endpoints`
- `EndpointSpec`:加静态工厂 `of(urlOrPath, method, enabled, withSession)`(绕过 JSON,parse 保留)
- `SubSystemApiConfigServiceImpl`:
  - create/update:主表 + 级联接口行(按 subSystemId 逻辑删后批量插,保持现有 invalidate 工厂逻辑)
  - buildRespList 组装 endpoints
  - `resolveEndpointJson` → 按 purpose 查接口行构建 EndpointSpec(testInvoke 的 apiKey 语义不变;auth 仍读主表 auth_config)
  - `pushExternalRoleCreate`/`queryExternalRoleIds`/`listRoleCreateApis`/`isCreateEndpointEnabled` 全部改为查接口行;**收敛 3 处重复的"create 端点启用"判断**(Factory.isConfigured、SubSystemEmployeeServiceImpl.isCreateEndpointEnabled 统一改调 ApiConfigService)
- `SubSystemEmployeeApiFactory` + `CamstarEmployeeApiAdapter` + `GenericHttpEmployeeApiAdapter`:构造改为 `(config, 接口行列表)`,适配器内部按 purpose 取 EndpointSpec(行为零变化,team_combo/role_query 无行=null 保持可选语义)
- `SubSystemEmployeeServiceImpl`:isCreateEndpointEnabled 删除改走统一方法;getRegisterableApis 改查接口行
- 测试 schema `src/test/resources/sql/create_tables.sql` 同步新表、删主表旧列

Controller 路由、权限注解全部不动(仅 VO 内部结构变化)。

## 三、前端(`jonhonjump-ui/jonhonjump-ui-admin-vue2`)

`src/views/system/subSystem/apiConfig/index.vue`:
- 树改为固定分组渲染:系统根 →「人员接口」(query/create/update/delete/team_combo)→「角色接口」(role_*)→「其他接口」(purpose 为空的自定义行);数据源 = config.endpoints(不再有 catalogMap/buildDefaultCatalog/normalizeCatalog/stripAuthNodes/apiCatalog)
- 叶子编辑表单字段不变(name/purpose/method/url/enabled/withSession)
- 保存 payload:`{id, subSystemId, apiType, baseUrl, authType, authConfig, endpoints:[...], paramMapping, responseMapping, deleteTip, connectTimeoutMs, readTimeoutMs, status}`
- 新增接入向导:camstar 按默认模板生成 8 行接口记录;http 生成空行
- 会话鉴权卡片、在线测试(apiKey=purpose / auth)、baseUrl 提取逻辑均不变
- `api/system/subSystemApiConfig.js` 无需改动

## 五、说明与不做的事

- **不改变任何请求行为**:适配器最终发出的请求与现在完全一致;Base-64 黄屏问题按之前给出的 curl/F12 路径继续排查(重构后每个接口一行、URL 直接可见,反而便于核对)
- 前后端需同版本部署(list/get/update 契约变更);现场执行迁移前建议备份
- 不新增 team_combo 在线测试能力(维持现状 apiKey 集合)
